배색의 원리(3속성, 명도, 색상환)는 [[색채-이론]]에 있다. 이 문서는 그 원리를 웹에서 구현하는 방법을 다룬다.

## 색을 역할별로 나누기

웹 화면에 필요한 색은 생각보다 적다. 보통 이렇게 나눈다.

| 역할 | 쓰는 곳 | 개수 |
| --- | --- | --- |
| **배경과 면** | 페이지 배경, 카드, 표 머리 | 2~3단계 |
| **글자** | 본문, 흐린 보조 글자 | 2단계 |
| **선** | 테두리, 구분선 | 1~2단계 |
| **강조색** | 링크, 버튼, 선택된 메뉴 | 1개 + 진한 버전, 옅은 버전 |
| **상태색** | 오류(빨강), 성공(초록), 경고(노랑), 안내(파랑) | 필요할 때만 |

배경·글자·선은 모두 **회색 계열**이다. 유채색은 강조색 하나뿐이다. [[색채-이론#비율이-더-중요하다|60-30-10 규칙]]을 웹에 옮기면 대략 이런 모양이 된다.

이 위키의 실제 색 변수는 다음과 같다(`src/styles/global.css`).

```css
:root {
  --accent: #2f4f73;         /* 포인트 컬러 (링크, 강조) */
  --accent-strong: #233c58;  /* 마우스를 올렸을 때 */
  --accent-soft: #e8eef5;    /* 옅은 강조 배경 (태그) */

  --bg: #f8f9fb;             /* 페이지 배경 */
  --surface: #ffffff;        /* 카드 */
  --surface-2: #f1f3f6;      /* 표 머리, 인용문 배경 */
  --text: #1c222a;           /* 본문 */
  --muted: #5d6875;          /* 날짜, 설명 같은 보조 글자 */
  --border: #e1e5ea;         /* 테두리 */
}
```

- 회색에 **파란 기운을 아주 조금** 섞었다(`#1c222a`, `#5d6875`). 강조색이 파랑이라 순수 회색보다 잘 어울린다.
- 페이지 배경(`--bg`)을 순수 흰색이 아닌 아주 옅은 회색으로 두고, 카드(`--surface`)를 흰색으로 해서 카드가 살짝 떠 보이게 했다.

### HSL로 색 다루기

CSS의 `hsl(색상 채도% 밝기%)`는 사람이 생각하는 방식과 비슷해서 색을 조절하기 쉽다.

```css
--accent:        hsl(212 42% 32%);  /* #2f4f73 기본 */
--accent-strong: hsl(212 43% 24%);  /* #233c58 밝기만 낮춤 → 같은 계열의 진한 색 */
--accent-soft:   hsl(212 39% 94%);  /* #e8eef5 밝기만 높임 → 같은 계열의 옅은 색 */
```

이 위키의 강조색 세 개를 HSL로 바꿔 보면 색상(212)은 그대로 두고 밝기만 바꾼 것이다.

다만 HSL의 밝기는 **눈이 느끼는 밝기와 다르다.** 같은 50%라도 노랑은 밝아 보이고 파랑은 어두워 보인다. 최신 CSS의 `oklch()`는 눈이 느끼는 밝기에 맞춰 설계되어서, 색상만 바꿔도 비슷한 밝기의 색을 만들기 쉽다.

## 대비 비율

**대비 비율**은 글자와 배경의 밝기 차이를 숫자로 나타낸 값이다. 1 : 1(같은 색)부터 21 : 1(검정과 흰색)까지 있다.
웹 접근성 국제 기준인 WCAG 2는 다음 값을 요구한다.

| 대상 | AA (최소 기준) | AAA (높은 기준) |
| --- | --- | --- |
| 일반 본문 | **4.5 : 1** | 7 : 1 |
| 큰 글자 (약 24px 이상, 또는 굵은 약 18.5px 이상) | 3 : 1 | 4.5 : 1 |
| 아이콘, 입력창 테두리 같은 UI 요소 | 3 : 1 | |

- 흰 배경 위 회색 글자는 `#767676`이 4.5 : 1을 겨우 넘는 경계다. 이보다 연하면 본문으로 쓰기 어렵다.
- 연한 회색 위에 연한 회색 글씨는 세련돼 보여도 햇빛 아래 휴대폰이나 저가형 모니터에서는 거의 안 보인다.
- 비활성화된 버튼처럼 **일부러 흐리게 만든 요소**는 기준에서 빠진다.

### 이 위키의 대비

| 조합 | 대비 | 판정 |
| --- | --- | --- |
| 본문 `#1c222a` / 배경 `#f8f9fb` | 15.2 : 1 | AAA |
| 보조 글자 `#5d6875` / 배경 `#f8f9fb` | 5.4 : 1 | AA |
| 링크 `#2f4f73` / 배경 `#f8f9fb` | 8.0 : 1 | AAA |
| 다크 모드 본문 `#dde3ea` / 배경 `#0e1218` | 14.5 : 1 | AAA |
| 다크 모드 보조 글자 `#8e9aa8` / 배경 `#0e1218` | 6.6 : 1 | AA |

### 확인하는 방법

- **[[크롬-개발자-도구]]:** 요소 검사(Elements) 탭에서 `color` 값 옆의 색 네모를 누르면 색 선택 창에 대비 비율과 AA·AAA 통과 여부가 바로 보인다.
- **Lighthouse:** 개발자 도구의 Lighthouse 탭에서 접근성 검사를 돌리면 대비가 부족한 글자를 모두 찾아준다.

## 다크 모드

다크 모드는 **라이트 모드의 색을 뒤집는 것이 아니다.** 어두운 배경에서는 눈이 색을 다르게 느끼기 때문에 색을 따로 정해야 한다.

![[웹-다크-모드-대비.svg]]

위 그림은 이 위키의 링크 색이다. 라이트 모드의 `#2f4f73`을 다크 모드에 그대로 쓰면 대비가 2.2 : 1밖에 안 되어 거의 안 보인다. 그래서 다크 모드에서는 밝힌 `#8fb0d8`(8.4 : 1)을 쓴다.

### 주의할 점

- **배경을 순수 검정(`#000`)으로 하지 않는다.** 순수 검정 위의 흰 글자는 대비가 너무 강해서 글자가 번져 보이고 눈이 피로하다. 구글 머티리얼 디자인은 `#121212`를 권한다. 이 위키는 파란 기운이 도는 `#0e1218`을 쓴다.
- **글자도 순수 흰색 대신** 조금 어두운 색을 쓴다. 이 위키는 `#dde3ea`다.
- **강조색은 밝히고 채도를 낮춘다.** 라이트 모드의 진하고 선명한 색은 어두운 배경에서 안 보이거나, 반대로 형광처럼 눈이 아프다.
- **그림자 대신 밝기로 높이를 표현한다.** 어두운 배경에서는 그림자가 잘 안 보인다. 위로 떠 있는 요소일수록 배경을 조금 더 밝게 한다. 이 위키도 배경 `#0e1218` → 카드 `#151b23` → 표 머리 `#1b222c` 순서로 밝아진다.
- **이미지를 확인한다.** 흰 배경의 그림이나 투명 배경의 검은 아이콘은 다크 모드에서 튀거나 사라진다. 이 위키의 설명 그림은 흰 배경을 넣어 두어서 어느 모드에서든 똑같이 보인다.

### 테마 전환 구현

다크 모드는 보통 두 가지를 함께 지원한다.

1. **시스템 설정 따르기:** 운영체제가 다크 모드면 사이트도 다크 모드로.
2. **직접 고르기:** 사이트의 버튼으로 바꾸고, 그 선택을 기억하기.

CSS만으로 시스템 설정을 따르려면 미디어 쿼리를 쓴다.

```css
@media (prefers-color-scheme: dark) {
  :root {
    --bg: #0e1218;
    --text: #dde3ea;
  }
}
```

직접 고르기까지 지원하려면 `<html>`에 테마 표시를 달고, 그 표시에 따라 변수를 바꾼다. 이 위키는 이렇게 한다.

```css
:root[data-theme='dark'] {
  --accent: #8fb0d8;
  --bg: #0e1218;
  /* ... */
  color-scheme: dark;  /* 스크롤바, 입력창 같은 브라우저 기본 요소도 어둡게 */
}
```

```js
// 화면이 그려지기 전에 실행해서 깜빡임을 막는다. 저장된 선택 → 시스템 설정 순
let theme;
try { theme = localStorage.getItem('theme'); } catch {}
if (theme !== 'light' && theme !== 'dark') {
  theme = matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light';
}
document.documentElement.dataset.theme = theme;
```

이 스크립트를 `<head>` 안에 바로 넣는 것이 중요하다. 페이지를 다 그린 뒤에 테마를 바꾸면 흰 화면이 한 번 번쩍인다.

## 상태색과 접근성

- 오류는 빨강, 성공은 초록처럼 **관습을 따른다.** 사용자가 이미 익숙한 의미를 거스르면 혼란스럽다.
- 상태를 **색만으로 알리지 않는다.** 입력칸 테두리만 빨갛게 바꾸지 말고, 아이콘과 "이메일 형식이 맞지 않습니다" 같은 문구를 함께 보여준다. [[색채-이론#색에만-의존하지-않기|색각 이상]]이 있는 사람도 알아볼 수 있어야 한다.
- 키보드로 이동할 때 보이는 **초점 표시(focus)**를 지우지 않는다. 이 위키는 `:focus-visible`에 강조색 테두리를 준다.
