글꼴 분류, 간격, 한글 글꼴의 특징 같은 원리는 [[타이포그래피]]에 있다. 이 문서는 웹에서 구현하는 방법을 다룬다.

## 글자 크기 단위

| 단위 | 기준 | 쓰는 곳 |
| --- | --- | --- |
| `px` | 화면의 점(CSS 픽셀) | 테두리 두께처럼 바뀌면 안 되는 값 |
| `rem` | **최상위(`<html>`) 글자 크기**. 기본 16px | 글자 크기, 여백 |
| `em` | **자기 자신(또는 부모)의 글자 크기** | 글자 크기에 비례해야 하는 값 (버튼 안쪽 여백, 코드 글자) |

- 글자 크기는 `rem`을 쓰는 것이 좋다. 사용자가 브라우저 설정에서 기본 글자 크기를 키우면 `rem`으로 정한 글자도 함께 커진다.
- `em`은 부모를 따라 계속 곱해져서, 목록 안의 목록처럼 겹치면 점점 작아지거나 커지는 문제가 있다.

## 크기 단계

[[타이포그래피#크기-단계-타입-스케일|타입 스케일]]을 CSS 변수로 정해 두고 그 값만 쓴다.

```css
:root {
  --text-sm:   0.8rem;    /* 12.8px  캡션, 태그 */
  --text-base: 1rem;      /* 16px    본문 */
  --text-lg:   1.25rem;   /* 20px    소제목 */
  --text-xl:   1.563rem;  /* 25px    제목 */
  --text-2xl:  1.953rem;  /* 31.25px 큰 제목 */
}
```

이 위키의 본문 영역은 대략 1.2배 비율이다.

| 요소 | 크기 |
| --- | --- |
| 본문 | 16px (`1rem`) |
| 표 | `0.94rem` |
| 소제목 (h3) | `1.2rem` |
| 제목 (h2) | `1.45rem` + 아래 구분선 |

### 화면 크기에 따라 바뀌는 글자

큰 제목은 휴대폰에서 너무 크고, 모니터에서는 너무 작을 수 있다. `clamp(최소, 기본, 최대)`로 화면 너비에 따라 자연스럽게 바꾼다.

```css
h1 {
  /* 최소 1.75rem, 화면 너비에 비례해 커지다가, 최대 3rem */
  font-size: clamp(1.75rem, 1.2rem + 2.5vw, 3rem);
}
```

기본값에 `vw`만 쓰지 않고 `rem`을 더하는 이유는, `vw`만 쓰면 사용자가 브라우저 글자 크기를 키워도 반응하지 않기 때문이다.

본문은 화면 크기와 상관없이 **16px 이상**으로 고정하는 편이 좋다. 휴대폰에서 16px보다 작은 입력칸을 누르면 iOS 사파리가 화면을 자동으로 확대해 버리는 문제도 있다.

## 행간과 줄 길이

```css
body {
  font-size: 1rem;
  line-height: 1.7;   /* 단위 없이 쓴다 */
}

h1, h2, h3 {
  line-height: 1.35;  /* 제목은 좁게 */
}

.prose {
  max-width: 40em;    /* 한글 한 글자는 약 1em → 한 줄 최대 40자 정도 */
}
```

- **`line-height`는 단위 없이** 숫자로 쓴다. `1.7`은 "자기 글자 크기의 1.7배"라서, 안쪽 요소의 글자 크기가 달라도 비율이 유지된다. `27px`처럼 고정하면 큰 글자의 줄이 겹친다.
- 한글 본문은 라틴 문자보다 넓게 1.6~1.8이 읽기 좋다. 이 위키 본문은 1.7이다.
- 줄 길이는 `max-width`로 제한한다. 한글은 한 글자가 대략 `1em`이고, 영문 기준이라면 `ch` 단위(숫자 0의 폭)를 쓴다. 이 위키는 넓은 화면에서 본문이 사이드바와 목차 사이에 놓여서 한 줄이 35자 안팎이다.

## 웹폰트

사용자의 컴퓨터에 없는 글꼴은 **웹폰트**로 내려받아 쓴다.

### 대체 글꼴 순서

글꼴은 여러 개를 순서대로 적는다(폰트 스택). 앞의 글꼴이 없거나 아직 내려받는 중이면 다음 글꼴을 쓴다.

```css
--font: 'Pretendard Variable', Pretendard, -apple-system, BlinkMacSystemFont,
        system-ui, 'Apple SD Gothic Neo', 'Noto Sans KR', sans-serif;
```

이 위키의 글꼴 설정이다. Pretendard가 없으면 맥의 시스템 글꼴, 그다음 윈도우·안드로이드의 시스템 글꼴, 마지막으로 브라우저 기본 고딕을 쓴다.

### 한글 웹폰트는 무겁다

[[타이포그래피#한글-글꼴을-만들기-어려운-이유|한글은 글자 수가 많아서]] 글꼴 파일 하나가 수 MB나 된다. 영문 글꼴은 보통 수십 KB다.

| 방법 | 설명 |
| --- | --- |
| **WOFF2 형식** | 웹용으로 압축한 글꼴 형식. 지금은 이것만 쓰면 된다 |
| **서브셋** | 자주 쓰는 글자(예: 2,350자)만 남긴 파일. 크기가 크게 줄지만, 빠진 글자는 다른 글꼴로 보인다 |
| **다이나믹 서브셋** | 글꼴을 글자 범위별로 수십~수백 조각으로 나누고, CSS `unicode-range`로 **그 페이지에 실제로 나온 글자가 든 조각만** 내려받는다 |
| **가변 글꼴 (Variable Font)** | 굵기 100~900을 파일 하나에 담는다. 굵기마다 파일을 따로 받을 필요가 없다 |

이 위키는 Pretendard의 **가변 글꼴 + 다이나믹 서브셋** 버전을 쓴다.

```html
<link rel="stylesheet"
  href="https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/variable/pretendardvariable-dynamic-subset.min.css" />
```

### 글꼴이 늦게 올 때

웹폰트를 내려받는 동안 글자를 어떻게 보여줄지는 `font-display`로 정한다.

| 값 | 동작 |
| --- | --- |
| `swap` | 먼저 대체 글꼴로 보여주고, 다 받으면 바꾼다. 글자가 바로 보이지만 바뀔 때 화면이 살짝 움직인다 |
| `block` | 잠깐(최대 약 3초) 글자를 숨기고 기다린다 |
| `optional` | 아주 짧게 기다려서 못 받으면 이번 방문에는 대체 글꼴을 계속 쓴다 |

본문은 보통 `swap`을 쓴다. 글자가 안 보이는 것보다 글꼴이 바뀌는 것이 낫기 때문이다.

## 한글 줄바꿈

브라우저는 기본적으로 한글을 **글자 단위**로 줄바꿈한다. 그래서 단어가 중간에서 잘린다.

```text
기본값                     keep-all
이 문서는 웹 타이포그래      이 문서는 웹
피를 정리한다.              타이포그래피를 정리한다.
```

```css
body {
  word-break: keep-all;       /* 한글도 띄어쓰기(어절) 단위로 줄바꿈 */
  overflow-wrap: anywhere;    /* 긴 URL처럼 띄어쓰기가 없는 문자열은 넘치지 않게 끊는다 */
}
```

이 위키도 이 두 줄을 쓴다. `keep-all`만 쓰면 긴 주소나 코드가 화면 밖으로 삐져나오기 때문에 `overflow-wrap`을 함께 쓴다.

최신 브라우저에는 `word-break: auto-phrase`(구절 단위로 자연스럽게 끊기)와 `text-wrap: balance`(제목 줄 길이를 고르게 맞추기)도 있다. 다만 지원하는 브라우저가 아직 일부이고, `auto-phrase`는 현재 일본어 위주로 동작한다.

## 자간

```css
h1, h2, h3, h4 { letter-spacing: -0.01em; }
```

- 큰 제목은 글자 사이가 넓어 보여서 살짝 좁힌다. 이 위키는 제목에 `-0.01em`을 준다.
- 본문의 자간은 건드리지 않는 것이 좋다. Pretendard처럼 화면용으로 만든 글꼴은 기본 간격이 이미 맞춰져 있다.
- `em` 단위를 쓰면 글자 크기가 바뀌어도 비율이 유지된다.
