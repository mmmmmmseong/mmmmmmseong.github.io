여백과 그리드의 원리는 [[구도와-레이아웃]]에 있다. 이 문서는 웹에서 구현하는 방법을 다룬다.

## 간격 체계

여백을 그때그때 정하지 않고, **몇 가지 값만 정해 두고** 그 안에서만 쓴다. 흔히 4나 8의 배수를 쓴다(8pt 그리드).

```css
:root {
  --space-1: 4px;
  --space-2: 8px;
  --space-3: 12px;
  --space-4: 16px;
  --space-5: 24px;
  --space-6: 32px;
  --space-7: 48px;
  --space-8: 64px;
}
```

- 13px, 17px, 22px처럼 마구 정한 값이 섞이면, 차이가 작아서 **의도가 아니라 실수**처럼 보인다.
- 값이 몇 개로 정해지면 "여기는 8일까 10일까" 고민하지 않아도 된다.
- 단계는 작은 값에서는 촘촘하고 큰 값으로 갈수록 벌어진다. 4와 8의 차이는 크게 느껴지지만 48과 52의 차이는 거의 느껴지지 않기 때문이다.

## 근접 원칙과 여백

![[웹-여백과-근접.svg]]

여백의 크기 차이가 곧 [[게슈탈트-원리#근접성-proximity|근접성]]이다. 왼쪽은 모든 간격이 같아서 어디까지가 한 덩어리인지 알 수 없다. 오른쪽은 간격만 바꿨는데 세 덩어리로 바로 보인다.

규칙은 하나다.

> **안쪽 간격 < 바깥쪽 간격**

- 제목과 그 아래 본문 사이 < 본문과 다음 제목 사이
- 카드 안의 요소 사이 < 카드와 카드 사이
- 입력칸과 그 이름표 사이 < 입력칸과 다음 입력칸 사이

이 위키의 소제목도 이렇게 되어 있다.

```css
.prose h2 { margin-top: 2.2em; padding-bottom: 0.3em; }  /* 위는 넓게 */
.prose p  { margin: 0.9em 0; }                            /* 문단 사이는 좁게 */
```

## 배치 도구: Flexbox와 Grid

CSS에는 요소를 배치하는 도구가 두 가지 있다.

| | Flexbox | Grid |
| --- | --- | --- |
| 방향 | **한 방향**(가로 또는 세로)으로 늘어놓기 | **가로세로 두 방향**을 함께 나누기 |
| 기준 | 내용의 크기에 맞춰 배치 | 미리 정한 칸에 맞춰 배치 |
| 잘 맞는 곳 | 메뉴, 버튼 묶음, 태그 목록, 카드 안의 한 줄 | 페이지 전체 틀, 카드 목록, 사진 모음 |

두 도구 모두 `gap`으로 요소 사이 간격을 정한다. 요소마다 `margin`을 주는 것보다 간단하고, 맨 끝에 불필요한 여백이 남지 않는다.

### Flexbox 예: 태그 목록

```css
.tags {
  display: flex;
  flex-wrap: wrap;   /* 넘치면 다음 줄로 */
  gap: 6px;
}
```

이 위키의 태그 목록이다. 태그 개수가 몇 개든 줄을 바꿔 가며 늘어놓는다.

### Grid 예: 12칸 그리드

```css
.grid {
  display: grid;
  grid-template-columns: repeat(12, 1fr);  /* 같은 너비 12칸 */
  gap: 24px;                               /* 거터 */
}

.main    { grid-column: span 8; }  /* 8칸 차지 */
.sidebar { grid-column: span 4; }  /* 4칸 차지 */
```

`fr`은 "남은 공간을 나눈 몫"이다. `1fr 2fr`이면 남은 공간을 1 : 2로 나눈다.

### Grid 예: 카드 목록

화면 너비에 따라 카드 개수가 저절로 바뀌는 목록은 한 줄로 만들 수 있다.

```css
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(260px, 1fr));
  gap: 16px;
}
```

카드 한 장이 최소 260px이 되도록, 들어갈 수 있는 만큼 칸을 만든다. 휴대폰에서는 1개, 태블릿에서는 2개, 모니터에서는 3~4개가 된다. 미디어 쿼리가 필요 없다.

## 반응형 레이아웃

**반응형**은 화면 너비에 따라 배치를 바꾸는 것이다. 미디어 쿼리로 "화면이 이 너비 이하일 때"의 규칙을 따로 적는다.

이 위키의 문서 페이지가 좋은 예다.

```css
.layout {
  display: grid;
  grid-template-columns: 240px minmax(0, 1fr) 200px;  /* 사이드바 | 본문 | 목차 */
  gap: 40px;
}

@media (max-width: 1100px) {
  .layout { grid-template-columns: 220px minmax(0, 1fr); }  /* 목차를 뺀다 */
}

@media (max-width: 820px) {
  .layout { grid-template-columns: 1fr; }  /* 한 단으로 */
}
```

| 화면 너비 | 배치 |
| --- | --- |
| 1100px 초과 | 사이드바 · 본문 · 목차 3단 |
| 821 ~ 1100px | 사이드바 · 본문 2단 |
| 820px 이하 | 본문 1단 |

- 본문 칸에 `1fr` 대신 `minmax(0, 1fr)`을 쓰는 이유가 있다. 표나 코드 블록처럼 긴 내용이 있을 때 칸이 내용에 밀려 화면 밖으로 넓어지는 것을 막는다.
- 바꾸는 기준 너비(브레이크포인트)는 기기 종류에 맞추기보다, **배치가 실제로 답답해지는 지점**에 둔다.

### 바깥 여백과 최대 너비

```css
.container {
  max-width: 1120px;  /* 넓은 모니터에서 너무 퍼지지 않게 */
  margin: 0 auto;     /* 가운데 정렬 */
  padding: 0 16px;    /* 휴대폰에서 글자가 화면 끝에 붙지 않게 */
}
```

이 위키의 전체 틀이다. 휴대폰 화면의 **좌우 여백 16px**은 가장 흔히 쓰는 값이다.

## 터치 영역

손가락은 마우스 포인터보다 훨씬 굵다. 누르는 요소는 **보이는 크기보다 누를 수 있는 영역**이 중요하다.

| 기준 | 최소 크기 |
| --- | --- |
| WCAG 2.2 (AA) | 24 × 24px |
| 애플 휴먼 인터페이스 가이드라인 | 44 × 44pt |
| 구글 머티리얼 디자인 | 48 × 48dp |

- 아이콘은 작아도 되지만, 안쪽 여백(`padding`)으로 누르는 영역을 넓힌다.
- 누르는 요소끼리 너무 붙어 있으면 옆의 것을 잘못 누른다. 사이에 최소 8px 정도는 띄운다.
