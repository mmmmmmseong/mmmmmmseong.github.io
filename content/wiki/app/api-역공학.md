공식 API가 없는 서비스의 데이터를 쓰려면, 웹페이지가 서버와 주고받는 요청을 직접 분석해야 한다.
School Helper는 이 방법으로 컴시간 시간표 데이터를 읽었다.

## 1. 요청 찾기

1. 브라우저에서 서비스 페이지를 열고 **개발자 도구(F12) → 네트워크 탭**을 켠다.
2. 학교 선택, 반 선택처럼 화면을 바꾸는 동작을 하면서 **새로 생기는 요청**을 본다.
3. 응답 크기가 크거나 JSON이 담긴 요청이 보통 데이터 요청이다.

## 2. 요청 분석하기

요청에서 확인할 것:

| 항목 | 확인할 것 |
| --- | --- |
| 주소와 쿼리 | 어떤 값이 바뀌는지 (학교 코드, 주차 등) |
| 인코딩 | Base64 같은 인코딩이 있는지 |
| 헤더 | `Referer`, `User-Agent`가 없으면 거절하는지 |
| 응답 | 형식(JSON, HTML)과 문자 인코딩 |

컴시간은 쿼리 문자열을 **Base64로 인코딩**해서 보냈다. Base64는 암호화가 아니라서 그대로 디코딩해 보면 구조가 보인다. ([[웹-정찰#인코딩은-암호화가-아니다|인코딩은 암호화가 아니다]])

```dart
final query = '..._${schoolCode}_0_$weekType';           // 분석으로 알아낸 형식
final base64Query = base64.encode(utf8.encode(query));
```

## 3. 응답 구조 추리하기

응답 JSON의 키 이름이 의미 없는 이름(`자료481` 등)이라 **값을 보고 추리**해야 했다.

- 선생님 이름 목록, 과목 이름 목록처럼 **문자열 배열**인 키를 먼저 찾는다.
- 숫자로 가득한 큰 배열은 시간표 본체일 가능성이 높다. 중첩 깊이를 세어보니 `학년 > 반 > 요일 > 교시` 4단계였다.
- 각 칸의 숫자는 **과목 번호와 교사 번호를 합친 값**이었다. 실제 시간표와 비교해서 나누는 규칙을 찾았다.

```dart
final teacherIdx = code % 100;          // 뒤 두 자리: 교사 번호
final subjectIdx = (code ~/ 100) ~/ 10; // 앞자리: 과목 번호
```

**알고 있는 정답(내 반 시간표)과 비교하는 것**이 가장 확실한 검증 방법이다.

## 4. 예의 지키기

- **요청을 최소로:** 응답을 기기에 캐시해서 같은 요청을 반복하지 않는다. School Helper는 약 64KB의 응답 전체를 저장해 두고 쓴다.
- **이용약관 확인:** 데이터 수집을 금지하는 서비스도 있다.
- **개인정보 주의:** 응답에 개인정보가 섞여 있으면 저장하거나 공개하지 않는다.
- **비공식 API는 언제든 바뀐다.** 응답이 달라져도 앱이 죽지 않게 예외 처리를 넉넉히 한다.
