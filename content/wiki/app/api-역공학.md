> 관련 프로젝트: [[schoolhelper|스쿨헬퍼]] ([[schoolhelper-v1|v1: 컴시간 역공학]]) · [GitHub](https://github.com/mmmmmmseong/schoolhelper)

공식 API가 없는 서비스의 데이터를 쓰려면, 웹페이지가 서버와 주고받는 요청을 직접 분석해야 한다.
스쿨헬퍼 첫 버전은 이 방법으로 컴시간 시간표 데이터를 읽었다.

> 2026년 11월 컴시간이 요청 토큰과 응답 암호화를 도입한 뒤로는, 그 장치를 풀지 않고 NEIS 공식 API로 바꿨다. **보호 장치가 없는 공개 응답을 브라우저처럼 읽는 것**과 **일부러 넣은 보호 장치를 해제하는 것**은 다르다. 결정 과정은 [[schoolhelper-v2#우회하지-않기로-한-이유|스쿨헬퍼 v2]]에 있다.

## 1. 요청 찾기

1. 우선 브라우저에서 서비스 페이지를 열고 **개발자 도구(F12) → 네트워크 탭**을 켜보자. ([[크롬-개발자-도구]])
2. 학교 선택, 반 선택처럼 화면을 바꾸는 동작을 하면, **새로 생기는 요청**을 확인할 수 있다.
3. 응답 크기가 크거나 JSON이 담긴 요청이 보통 데이터 요청이다.

## 2. 요청 분석하기

이때 요청에서 확인해볼 것은 다음과 같다.

| 항목 | 확인할 것 |
| --- | --- |
| 주소와 쿼리 | 어떤 값이 바뀌는지 (학교 코드, 주차 등) |
| 인코딩 | Base64 같은 인코딩이 있는지 |
| 헤더 | `Referer`, `User-Agent`가 없으면 거절하는지 |
| 응답 | 형식(JSON, HTML)과 문자 인코딩 |

컴시간은 쿼리 문자열을 **Base64로 인코딩**해서 보냈다. Base64는 암호화가 아니라서 그대로 디코딩해 보면 구조가 보인다. ([[웹-정찰#인코딩은-암호화가-아니다|인코딩은 암호화가 아니다]])

```dart
final query = '..._${schoolCode}_0_$weekType';           // 분석으로 알아낸 형식
final base64Query = base64.encode(utf8.encode(query));
```

## 3. 응답 구조 추리하기

응답 JSON의 키 이름이 의미 없는 이름(`자료481` 등)이라 **값을 보고 추리**해야 했다.

- 선생님 이름 목록, 과목 이름 목록처럼 **문자열 배열**인 키를 먼저 찾아봤다.
- 숫자로 가득한 큰 배열은 시간표 본체일 가능성이 높다. 중첩 깊이를 세어보니 `학년 > 반 > 요일 > 교시` 4단계였다.
- 각 칸의 숫자는 **과목 번호와 교사 번호를 합친 값**이었다. 실제 시간표와 비교해서 나누는 규칙을 찾았다.

```dart
final teacherIdx = code % 100;          // 뒤 두 자리: 교사 번호
final subjectIdx = (code ~/ 100) ~/ 10; // 앞자리: 과목 번호
```

**알고 있는 정답(내 반 시간표)과 비교하는 것**이 가장 확실한 검증 방법이다.

## 4. 예의 지키기

- **요청을 최소로:** 응답을 기기에 캐시해서([[로컬-캐싱]]) 같은 요청을 반복하지 않도록 하자. 스쿨헬퍼 첫 버전은 약 64KB의 응답 전체를 저장해 두고 썼다.
- **이용약관 확인:** 데이터 수집을 금지하는 서비스도 있다.
- **개인정보 주의:** 응답에 개인정보가 섞여 있다면 저장하거나 공개하지 않도록 주의하자.
- **비공식 API는 언제든 바뀐다.** 응답이 달라져도 앱이 죽지 않게 예외 처리를 넉넉히 해두는 것이 좋다. 다만 오류를 조용히 삼키면 안 된다. 스쿨헬퍼는 오류를 `null`로 삼키는 바람에, 컴시간이 막힌 뒤에도 몇 달 전 캐시만 보이는 줄 몰랐다.

## 5. 막혔을 때: 기술적 보호 조치

서비스가 자동 수집을 막으려고 **일부러 장치를 넣는** 경우가 있다. 2026년 11월 컴시간이 그랬다.

| 장치 | 하는 일 |
| --- | --- |
| **요청 토큰** | 페이지를 열 때마다 새 토큰을 주고, 그 토큰이 없는 요청은 거절한다(403) |
| **응답 암호화** | 응답을 AES 등으로 암호화해서, 페이지의 스크립트만 풀 수 있게 한다 |
| **난독화** | 토큰을 만들고 암호를 푸는 스크립트를 읽기 어렵게 뒤섞는다 |
| **요청 제한, 차단** | 같은 IP에서 요청이 너무 많으면 막는다 |

이런 장치를 풀어서 읽는 방법이 공개되어 있어도, **그것을 쓰는 것은 다른 문제**다.

- **허락이 없다:** 보호 장치가 없을 때 공개된 응답을 브라우저처럼 받는 것과, **막으려고 넣은 장치를 해제**하는 것은 다르다. 서비스가 "자동 수집을 원하지 않는다"는 뜻을 분명히 밝힌 것이기 때문이다. 우회 코드의 오픈소스 라이선스는 그 코드를 쓸 권리일 뿐, 서비스의 허락이 아니다.
- **법적 위험:** 접근을 막는 장치를 무력화하면 [[정보통신망법]]의 무단 접근이나 저작권법의 기술적 보호조치 무력화 금지에 걸릴 수 있다.
- **계속 깨진다:** 서비스가 장치를 바꿀 때마다 다시 대응해야 한다. 컴시간을 우회하는 오픈소스 라이브러리도 사흘 사이에 대응 버전이 세 번 나왔다.
- **남에게 피해가 갈 수 있다:** 학생 폰마다 우회 요청을 보내면 학교 IP가 통째로 차단될 수 있다.

막혔다면 **공식 API가 있는지** 먼저 찾아보자. 스쿨헬퍼는 같은 시간표 데이터를 [[공공-오픈-api|NEIS 공식 API]]에서 받을 수 있었다. 공식 API가 없다면 서비스에 직접 문의하는 것이 정석이다.
