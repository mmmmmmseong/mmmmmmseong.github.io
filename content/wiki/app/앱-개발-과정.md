## 앱을 만드는 세 가지 방법

휴대폰은 크게 **안드로이드**와 **iOS(아이폰)** 두 종류다. 둘은 서로 다른 운영체제라서, 원래는 앱을 따로 만들어야 한다.

| 방법 | 언어 | 특징 | 예 |
| --- | --- | --- | --- |
| **네이티브** | 안드로이드: Kotlin, Java / iOS: Swift | 그 운영체제의 기능을 전부 쓸 수 있고 가장 빠르다. 대신 두 번 만들어야 한다 | [[planner|스터디 플래너]] (Kotlin) |
| **크로스플랫폼** | Flutter: Dart / React Native: 자바스크립트 | **코드 하나로** 안드로이드와 iOS 앱을 함께 만든다 | [[schoolhelper|스쿨헬퍼]] (Flutter) |
| **웹앱** | HTML, CSS, 자바스크립트 | 설치 없이 브라우저에서 연다. 폰의 기능은 제한적이다 | [[promptinjection|Break The AI]] |

어떤 방법을 고를지는 **필요한 기능**에 달렸다.
- 스터디 플래너는 잠금화면 위에 카드를 띄우는 안드로이드 전용 기능(접근성 서비스)이 핵심이라 네이티브로 만들었다.
- 스쿨헬퍼는 시간표와 공지를 보여주는 일반적인 화면이라, 안드로이드와 아이폰 학생 모두 쓸 수 있는 Flutter를 골랐다.

## Flutter와 Dart

**Flutter**는 구글이 만든 크로스플랫폼 앱 개발 도구다. **Dart**는 Flutter에서 쓰는 프로그래밍 언어다.

Flutter에서는 화면의 모든 것이 **위젯**이다. 글자, 버튼, 여백, 표까지 위젯을 레고처럼 끼워서 화면을 만든다.

```dart
Column(                         // 세로로 쌓기
  children: [
    Text('2-3 시간표'),          // 글자
    ElevatedButton(             // 버튼
      onPressed: refresh,       // 누르면 refresh 실행
      child: Text('새로고침'),
    ),
  ],
)
```

- 같은 코드로 안드로이드, iOS, 웹, 윈도우·맥 앱까지 만들 수 있다.
- 화면이 바뀌어야 할 때는 `setState()`를 불러서 "다시 그려라"라고 알린다.

## 코드가 앱이 되기까지: 빌드

내가 쓴 코드는 그대로 폰에서 실행되지 않는다. **빌드**라는 과정을 거쳐 설치 파일이 된다.

```text
Dart 코드 + 이미지·글꼴 등 리소스
   ↓ 컴파일: 폰이 실행할 수 있는 기계어로 바꾼다
   ↓ 묶기: 코드와 리소스를 파일 하나로 합친다
   ↓ 서명: 만든 사람의 디지털 서명을 붙인다
설치 파일 (안드로이드: APK / AAB, iOS: IPA)
```

| 파일 | 뜻 |
| --- | --- |
| **APK** | 안드로이드 설치 파일. 폰에 바로 설치할 수 있다 |
| **AAB** | 플레이 스토어에 올리는 형식. 스토어가 기기에 맞는 APK를 만들어 준다 |

빌드에는 두 종류가 있다.
- **디버그 빌드:** 개발용. 느리지만 오류 추적과 핫 리로드가 된다.
- **릴리스 빌드:** 배포용. 최적화되어 빠르고 작다.

빌드할 때 바깥에서 값을 넣을 수도 있다. 스쿨헬퍼는 NEIS 인증키를 코드에 적지 않고 빌드할 때 넣는다(`--dart-define-from-file`). → [[env로-api-키-관리]]

## 실제 폰으로 테스트하기

컴퓨터 안에서 가상 폰을 띄우는 **에뮬레이터**도 있지만, 실제 폰으로 확인하는 것이 가장 정확하다. 잠금화면이나 알림처럼 기기마다 다른 기능은 특히 그렇다.

안드로이드는 **adb**(Android Debug Bridge)라는 도구로 컴퓨터와 폰을 연결한다.

1. 폰의 **설정 → 휴대전화 정보 → 소프트웨어 정보**에서 빌드 번호를 일곱 번 누르면 **개발자 옵션**이 생긴다.
2. 개발자 옵션에서 **USB 디버깅** 또는 **무선 디버깅**을 켠다.
3. 무선 디버깅은 같은 와이파이에서 페어링 코드로 연결한다. 선 없이 설치와 테스트를 할 수 있다.

```text
adb devices          연결된 기기 목록
flutter run          연결된 폰에 빌드해서 설치하고 실행
```

## 핫 리로드

코드를 고칠 때마다 다시 빌드해서 설치하면 오래 걸린다. 스쿨헬퍼는 무선으로 APK를 설치하는 데 1~2분이 걸렸다.

Flutter의 **핫 리로드**는 바뀐 코드만 실행 중인 앱에 **바로 밀어 넣는다.** 1초 안에 화면이 바뀌고, 앱의 상태(지금 보고 있는 화면, 입력한 값)도 그대로 남는다.

| | 핫 리로드 | 핫 리스타트 | 다시 설치 |
| --- | --- | --- | --- |
| 속도 | 1초 안팎 | 몇 초 | 1~2분 |
| 앱 상태 | 유지 | 처음부터 | 처음부터 |
| 쓰는 때 | 화면 모양, 함수 내용 수정 | 처음 실행할 때 정해지는 값 수정 | 앱 설정·권한·라이브러리 변경 |

## 앱 ID

모든 앱에는 **앱 ID**(안드로이드에서는 패키지 이름)가 있다. 앱의 주민등록번호 같은 것이다.

```text
com.schoolhelper.main
```

- 인터넷 주소를 거꾸로 쓴 형식이다(`main.schoolhelper.com` → `com.schoolhelper.main`). 전 세계에서 겹치지 않게 하려는 것이다.
- 폰은 앱 ID로 앱을 구분한다. **ID를 바꾸면 다른 앱**으로 설치되어, 설정과 로그인이 처음부터 시작된다.
- Flutter 프로젝트를 처음 만들면 `com.example.프로젝트이름`으로 정해진다. 구글 플레이는 `com.example`로 시작하는 앱을 받지 않는다. 스쿨헬퍼도 `com.example.firstapp`에서 바꿨다.
- 앱 이름("스쿨헬퍼")은 홈 화면에 보이는 이름일 뿐이고, 언제든 바꿀 수 있다.

## 서명

설치 파일에는 만든 사람의 **디지털 서명**이 붙는다. [[대칭키와-공개키-암호#용도-2-전자-서명|전자 서명]]과 같은 원리다.

- 업데이트는 **같은 앱 ID + 같은 서명**일 때만 설치된다. 다른 사람이 같은 ID로 가짜 업데이트를 만들어도 서명이 달라서 설치되지 않는다.
- 서명 키를 잃어버리면 그 앱을 다시는 업데이트할 수 없다. 키 파일은 잘 보관해야 한다.

## 배포

| 방법 | 필요한 것 | 특징 |
| --- | --- | --- |
| **구글 플레이** | 개발자 등록(한 번 25달러), 심사 | 누구나 검색해서 설치. 자동 업데이트 |
| **APK 직접 설치** | 없음 | 파일을 보내 주고 "출처를 알 수 없는 앱" 설치를 허용해서 설치. 스터디 플래너가 이 방식이다 |
| **앱 스토어 (iOS)** | 맥 컴퓨터, 애플 개발자 계정(매년 99달러), 심사 | 아이폰 앱은 맥 없이 빌드할 수 없다 |
