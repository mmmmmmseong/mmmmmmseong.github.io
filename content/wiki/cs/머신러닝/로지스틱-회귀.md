## 로지스틱 회귀란

**로지스틱 회귀**는 "예 / 아니오"를 맞히는 **분류** 모델이다. 이름에 "회귀"가 들어가지만 분류에 쓴다.

구조가 단순해서 머신러닝을 처음 배울 때 가장 먼저 만나고, 실무에서도 기준 모델로 많이 쓴다.
- 계산이 빠르고, 데이터가 적어도 어느 정도 동작한다.
- 결과가 **가중치 숫자 몇 개**라서 "왜 이렇게 판단했는지" 볼 수 있다.

## 동작 원리

두 단계로 계산한다.

**1. 점수 매기기:** 특징마다 가중치를 곱해서 모두 더한다.

```text
점수 z = w₁·x₁ + w₂·x₂ + … + w₈·x₈ + b

x : 특징 (세로 위치, 숫자 비율, "안내" 포함 여부 …)
w : 가중치 (그 특징을 얼마나, 어느 방향으로 볼지)
b : 기본 점수 (절편)
```

**2. 확률로 바꾸기:** 점수를 **시그모이드 함수**에 넣으면 0~1 사이의 확률이 된다.

```text
확률 p = 1 / (1 + e^(−z))
```

![[시그모이드.svg]]

- 점수가 크면 확률이 1에 가깝고(제목일 가능성 높음), 작으면 0에 가깝다.
- 점수가 0이면 확률은 정확히 0.5다.
- 보통 확률 0.5를 기준으로 예 / 아니오를 나눈다. 하지만 꼭 0.5일 필요는 없다([아래](#문서-안에서-1등-고르기)).

## 학습이란

학습은 **정답을 가장 잘 맞히는 가중치(w, b)를 찾는 일**이다.

- 처음에는 가중치를 아무렇게나 정하고 예측해 본다.
- 정답이 "제목"인데 확률이 0.1로 나왔다면 많이 틀린 것이다. 틀린 정도를 **손실**(로그 손실)로 잰다.
- 손실이 줄어드는 방향으로 가중치를 조금씩 고치는 것을 반복한다.

scikit-learn에서는 이 과정이 한 줄이다.

```python
from sklearn.linear_model import LogisticRegression

model = LogisticRegression(class_weight='balanced')
model.fit(X_train, y_train)          # 학습: 가중치를 찾는다
p = model.predict_proba(X_test)[:, 1] # 추론: 제목일 확률
```

## 표준화

특징마다 숫자의 범위가 다르다. 세로 위치는 0~1인데 글자 수는 0~100이다. 이대로 학습하면 가중치 크기를 서로 비교할 수 없고, 학습도 불안정해진다.

**표준화**는 특징마다 평균을 빼고 표준편차로 나눠서, 모두 "평균 0, 퍼진 정도 1"로 맞추는 것이다.

```text
표준화한 값 = (원래 값 − 평균) / 표준편차
```

- 표준화하면 가중치의 **크기**로 특징의 중요도를 비교할 수 있다.
- 평균과 표준편차는 **학습용 데이터에서만** 계산한다. 시험용 데이터까지 넣어 계산하면 시험 문제를 미리 엿본 셈이 된다. → [[모델-평가#데이터-누수]]
- 앱에서 예측할 때도 학습 때 구한 **같은 평균과 표준편차**로 표준화해야 한다.

## 가중치 읽기

로지스틱 회귀의 장점은 학습 결과를 사람이 읽을 수 있다는 것이다. 표준화한 특징의 가중치는 이렇게 읽는다.

| 가중치 | 뜻 |
| --- | --- |
| 큰 양수 | 이 값이 클수록 "예"일 가능성이 크게 높아진다 |
| 큰 음수 | 이 값이 클수록 "아니오" 쪽이다 |
| 0에 가까움 | 판단에 별 영향이 없다 |

스쿨헬퍼 제목 모델에서는:
- **세로 위치**가 가장 강했다. 위에 있을수록 제목이다.
- **숫자 비율**이 높으면 제목이 아니다. 날짜나 표가 많은 줄이다.
- **"안내"**가 있으면 제목 쪽이다.
- 예상과 달리 **글자 크기**는 약했다.

이렇게 결과를 읽어 보면 **틀린 이유**도 보인다. 틀린 5장 중 3장은 "…안내드립니다."가 들어간 본문 줄을 골랐다. "안내" 특징이 문장 속 "안내드립니다"까지 잡았기 때문이다. 특징을 "안내"로 **끝나는** 줄로 바꾸는 것이 다음 개선 후보가 된다.

## 불균형 데이터

제목 줄은 문서마다 하나뿐이다. 그래서 줄의 98% 이상이 "제목 아님"이다. 이렇게 한쪽이 훨씬 많은 데이터를 **불균형 데이터**라고 한다.

- 그대로 학습하면 모델은 "전부 아니오"라고 답하는 쪽으로 기운다. 그래도 98%는 맞히기 때문이다.
- `class_weight='balanced'`를 주면 **적은 쪽을 틀렸을 때 더 크게 벌점**을 준다. 개수에 반비례하는 가중치를 붙이는 것이다.
- 평가할 때도 정확도만 보면 속는다. → [[모델-평가#정확도의-함정]]

## 문서 안에서 1등 고르기

확률 0.5를 기준으로 자르면, 한 문서에서 제목이 0개 또는 여러 개 나올 수 있다. 하지만 제목은 **문서마다 정확히 하나**다.

그래서 스쿨헬퍼는 기준값 대신 **문서 안에서 확률이 가장 높은 줄 하나**를 제목으로 고른다. 문제의 구조(정답이 하나)에 맞춰 모델의 출력을 쓰는 방법을 정한 것이다. 평가도 같은 방식으로 했다.

## 앱에 넣기

로지스틱 회귀의 학습 결과는 결국 **숫자 몇 개**다.

```json
{
  "features": ["글자 높이 비율", "세로 위치", "…"],
  "mean":     [ … ],
  "std":      [ … ],
  "weights":  [ … ],
  "bias":     …
}
```

(모양만 나타낸 예시다.)

그래서 앱에 머신러닝 라이브러리를 넣지 않아도 된다.

1. Python에서 학습하고, 특징 이름·평균·표준편차·가중치·절편을 JSON으로 내보낸다.
2. 앱에 JSON 파일을 넣는다.
3. 앱은 같은 방식으로 특징을 계산하고, 표준화하고, 가중치를 곱해 더한다.

주의할 점:
- **특징 계산이 Python과 완전히 같아야 한다.** 스쿨헬퍼는 같은 31장으로 두 결과를 비교해서, 점수 차이가 거의 0(0.000000000000007 이하)이고 31장 모두 같은 줄을 고르는 것을 확인했다.
- 모델 파일에 앱이 계산할 줄 모르는 특징이 있으면 **읽기를 거부**하게 했다. 조용히 틀린 답을 내는 것보다 낫다. → [[예외-처리#오류를-삼키면-안-된다]]
- 값이 없는 특징(예: 다른 기기에서 신뢰도가 안 나옴)은 학습 때의 **평균**을 넣는다. 표준화하면 0이 되어 점수에 영향을 주지 않는다.

## 장단점

| 장점 | 단점 |
| --- | --- |
| 단순하고 빠르다 | 특징 사이의 복잡한 관계는 잘 못 잡는다 |
| 데이터가 적어도 쓸 만하다 | 좋은 특징을 사람이 직접 만들어야 한다 |
| 가중치로 판단 이유를 읽을 수 있다 | 사진이나 긴 글을 그대로 넣을 수는 없다 |
| 결과가 숫자 몇 개라 어디에나 넣기 쉽다 | |

데이터가 많고 관계가 복잡하면 결정 트리, 신경망 같은 모델을 쓴다. 하지만 데이터가 수십 개뿐일 때는 단순한 모델이 오히려 안정적이다.
