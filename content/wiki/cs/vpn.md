## VPN이란

**VPN(Virtual Private Network, 가상 사설망)**은 누구나 쓰는 **공용 인터넷 위에, 나만 쓰는 사설망처럼 동작하는 통로**를 만드는 기술이다.

이름을 나눠 보면 뜻이 보인다.

| 단어 | 뜻 |
| --- | --- |
| **Private Network** (사설망) | 회사 안처럼 외부에서 들어올 수 없는, 우리끼리만 쓰는 네트워크 |
| **Virtual** (가상) | 실제로 전용선을 깐 것이 아니라, 인터넷 위에 **소프트웨어로 흉내 낸** 것 |

예전에는 서울 본사와 부산 지사를 사설망으로 이으려면 통신사에서 **전용 회선**을 빌려야 했다. 비싸고 느리게 설치됐다.
VPN은 이미 깔린 인터넷을 그대로 쓰면서, 그 위를 지나는 데이터를 **암호화해서 감싸** 전용선처럼 쓰게 해 준다.

## 두 가지 쓰임

VPN은 원래 회사용 기술이다. 요즘 광고에서 보는 "개인용 VPN"은 같은 기술을 다른 목적으로 쓰는 것이다.

| | 회사·학교 VPN (원래 용도) | 개인용 VPN 서비스 |
| --- | --- | --- |
| 목적 | 밖에서 **내부망에 들어가기** | 내 인터넷 통신을 **숨기거나 위치를 바꾸기** |
| 예 | 재택근무 중 사내 서버 접속, 학교 밖에서 도서관 논문 DB 접속 | 공용 와이파이 보호, 다른 나라 IP로 접속 |
| VPN 서버 위치 | 회사 내부망의 입구 | VPN 업체가 여러 나라에 둔 서버 |
| 터널을 지나는 것 | 내부망으로 가는 통신만 | 보통 **모든** 인터넷 통신 |

두 경우 모두 원리는 같다. **내 컴퓨터와 VPN 서버 사이에 암호화된 터널을 만들고, VPN 서버를 거쳐 목적지로 간다.**

## 핵심 원리 세 가지

VPN은 세 가지 기술의 조합이다.

1. **터널링:** 원래 패킷을 다른 패킷 안에 통째로 넣어 보낸다.
2. **암호화:** 넣은 패킷을 암호화해서 중간에서 못 보게 한다.
3. **인증:** 터널 반대편이 진짜 VPN 서버인지, 접속한 사람이 허락된 사람인지 확인한다.

### 1. 터널링

**터널링(Tunneling)**은 패킷을 **다른 패킷의 데이터 칸에 통째로 넣어서** 보내는 방법이다. [[osi-7계층#캡슐화|캡슐화]]를 한 번 더 하는 것이다.

![[vpn-패킷-구조.svg]]

- **VPN 없이:** IP 헤더에 "내 IP → 목적지 IP"가 그대로 적혀 있다. 중간의 공유기와 통신사는 내가 어디와 통신하는지 안다.
- **VPN 사용:** 원래 패킷(목적지 주소 포함)을 통째로 암호화한다. 그다음 "내 IP → VPN 서버 IP"라는 **새 겉봉투**를 씌운다. 중간에서는 VPN 서버와 무언가를 주고받는다는 것만 보인다.

편지를 다른 봉투에 넣어 보내는 것과 같다. 겉봉투에는 VPN 서버 주소만 적혀 있다. VPN 서버가 겉봉투를 뜯고 안의 편지를 진짜 목적지로 보낸다.

### 2. 암호화

터널 안의 패킷은 [[대칭키와-공개키-암호|암호화]]되어 있다. 방식은 HTTPS와 비슷하다.

- 처음 연결할 때 **공개키 암호와 키 교환**으로 양쪽만 아는 세션 키를 만든다.
- 이후의 패킷은 그 세션 키로 빠르게 **대칭키 암호화**한다. 주로 AES-GCM이나 ChaCha20-Poly1305를 쓴다.
- 패킷마다 **인증 태그**가 붙는다. 중간에서 한 비트라도 바꾸면 VPN 서버가 알아채고 버린다.

### 3. 인증

아무나 회사 VPN에 접속하면 안 되고, 가짜 VPN 서버에 연결돼도 안 된다. 그래서 양쪽을 확인한다.

- **서버 확인:** 인증서나 미리 알고 있는 공개키로 진짜 VPN 서버인지 확인한다.
- **사용자 확인:** 아이디·비밀번호, 인증서, OTP 같은 2단계 인증. 회사 VPN은 보통 사내 계정과 연동한다.

## 내 컴퓨터 안에서 일어나는 일

VPN 프로그램을 켜면 운영체제에 **가상 네트워크 장치**가 하나 생긴다. 리눅스에서는 `tun0`, `wg0`, 맥에서는 `utun0` 같은 이름이다.
랜선이나 와이파이 카드처럼 보이지만 실제 하드웨어는 없는 **소프트웨어 장치**다.

```text
브라우저
  ↓ 원래 패킷 (목적지: 142.250.1.1)
라우팅 테이블: "모든 통신은 가상 장치로 보내라"
  ↓
가상 장치 (wg0) ─ VPN 프로그램이 패킷을 받아 암호화하고 겉봉투를 씌움
  ↓ 새 패킷 (목적지: VPN 서버 5.6.7.8, UDP)
실제 장치 (와이파이) → 인터넷
```

1. VPN이 켜지면 **라우팅 테이블**이 바뀐다. 운영체제가 패킷을 어느 장치로 내보낼지 정하는 표다.
2. 브라우저는 평소처럼 패킷을 보낸다. 운영체제는 표에 따라 그 패킷을 가상 장치로 보낸다.
3. VPN 프로그램이 가상 장치에서 패킷을 꺼내 암호화하고, VPN 서버 주소로 겉봉투를 씌워 진짜 와이파이로 내보낸다.
4. 응답은 반대로 온다. VPN 프로그램이 복호화해서 가상 장치에 넣으면, 브라우저는 평소처럼 응답을 받는다.

**브라우저나 게임은 VPN이 있는지조차 모른다.** 운영체제 수준에서 처리되기 때문에, 프로그램을 고치지 않아도 모든 통신이 터널을 지난다.

가상 장치는 VPN 안에서 쓰는 **가상 IP 주소**도 받는다(예: `10.8.0.2`). 원래 패킷의 출발지는 이 가상 IP다. 회사 VPN이라면 이 주소 덕분에 내 노트북이 사내망 안의 컴퓨터처럼 취급된다.

## 데이터가 지나가는 길

![[vpn-경로.svg]]

1. 내 컴퓨터가 암호화한 패킷을 VPN 서버로 보낸다. 와이파이와 통신사는 겉봉투만 볼 수 있다.
2. VPN 서버가 겉봉투를 벗기고 복호화해서 원래 패킷을 꺼낸다.
3. VPN 서버는 출발지 주소를 **자기 공인 IP로 바꿔서** 목적지로 보낸다. 공유기의 [[ip-주소와-nat|NAT]]와 같은 원리다.
4. 목적지 사이트는 VPN 서버가 접속한 것으로 안다. 내 실제 IP는 모른다.
5. 응답은 VPN 서버로 돌아오고, VPN 서버가 다시 암호화해서 터널로 내게 보낸다.

그래서 VPN을 켜면 "내 IP"를 확인하는 사이트에 VPN 서버의 IP가 나온다. 일본에 있는 VPN 서버를 쓰면 사이트는 내가 일본에서 접속했다고 판단한다.

### 신뢰가 옮겨 갈 뿐이다

그림의 VPN 서버 칸을 보면, **VPN 서버는 내 실제 IP와 내가 가는 사이트를 모두 안다.**
VPN은 통신사와 와이파이 관리자로부터 숨겨 주는 대신, 그 정보를 **VPN 업체에 맡기는** 것이다. 엿볼 수 있는 사람이 사라지는 게 아니라 **바뀌는** 것이다.

- VPN 업체가 기록(로그)을 남기는지, 어느 나라 법을 따르는지가 중요하다.
- "무료 VPN"은 운영비를 어딘가에서 벌어야 한다. 광고, 사용자 데이터 판매, 심하면 악성 코드인 경우도 있다.

## 회사 VPN: 사설망에 들어가기

회사 내부 서버는 보통 `10.0.0.0/8` 같은 [[ip-주소와-nat#공인-ip와-사설-ip|사설 IP]]를 쓴다. 사설 IP는 인터넷에서 바로 접근할 수 없다. 밖에서는 `10.1.2.3`으로 가는 길 자체가 없다.

VPN으로 접속하면 이렇게 된다.

1. 내 노트북이 회사 VPN 서버와 터널을 만들고, 사내망 가상 IP(예: `10.8.0.25`)를 받는다.
2. `10.1.2.3`(사내 서버)으로 가는 패킷이 터널로 들어간다.
3. 회사 VPN 서버가 패킷을 꺼내 사내망에 풀어 놓는다. 사내 서버 입장에서는 사내망 안의 컴퓨터가 접속한 것과 같다.

### 전체 터널과 분할 터널

| 방식 | 터널로 보내는 것 | 특징 |
| --- | --- | --- |
| **전체 터널** (Full Tunnel) | 모든 통신 | 회사가 모든 통신을 보안 검사할 수 있다. 유튜브까지 회사를 거쳐서 느리다 |
| **분할 터널** (Split Tunnel) | 사내망 주소로 가는 통신만 | 나머지는 그냥 인터넷으로 나가서 빠르다. 대신 그 통신은 보호받지 못한다 |

라우팅 테이블에 "`10.0.0.0/8`만 가상 장치로"라고 적으면 분할 터널, "전부 가상 장치로"라고 적으면 전체 터널이다.

### 거점 간 VPN

사람이 아니라 **네트워크와 네트워크**를 잇는 방식도 있다. 서울 본사와 부산 지사의 라우터끼리 VPN 터널을 상시로 연결해 두면, 두 사무실이 하나의 사내망처럼 동작한다. 직원 컴퓨터에는 VPN 프로그램이 필요 없다. 이것을 **사이트 간(Site-to-Site) VPN**이라고 한다.

## VPN 프로토콜

터널을 어떻게 만들고 암호화할지 정한 규칙이다.

| 프로토콜 | 특징 | 주로 쓰는 곳 |
| --- | --- | --- |
| **IPsec** (IKEv2) | 운영체제에 기본으로 들어 있는 오래된 표준. 3계층(IP)에서 동작한다 | 거점 간 VPN, 회사 VPN, 휴대폰 기본 VPN |
| **OpenVPN** | TLS를 이용한다. 설정이 유연하고, TCP 443으로 돌리면 HTTPS처럼 보여 잘 막히지 않는다 | 개인용 VPN 서비스, 오래된 회사 VPN |
| **WireGuard** | 2020년 리눅스 커널에 들어간 최신 방식. 코드가 약 4,000줄로 짧아 검증이 쉽고 빠르다 | 개인용 VPN 서비스, Tailscale 같은 최신 도구 |
| **SSL VPN** | 브라우저나 전용 앱으로 HTTPS(443)를 통해 접속한다. 제품마다 방식이 다르다 | 회사 원격 근무 |
| ~~PPTP~~ | 1990년대 방식. 암호가 뚫려 있어 **쓰면 안 된다** | |

### WireGuard의 예

WireGuard는 설정 파일이 짧아서 VPN의 구성 요소가 한눈에 보인다.

```ini
[Interface]
PrivateKey = (내 개인키)
Address = 10.8.0.2/32          # 터널 안에서 쓸 내 가상 IP
DNS = 10.8.0.1                 # 터널 안에서 쓸 DNS 서버

[Peer]
PublicKey = (서버의 공개키)      # 이 공개키를 가진 서버만 믿는다
Endpoint = vpn.example.com:51820  # 겉봉투에 적힐 VPN 서버 주소 (UDP)
AllowedIPs = 0.0.0.0/0         # 모든 통신을 터널로 = 전체 터널
```

- `PrivateKey`, `PublicKey`: 인증과 키 교환에 쓰는 [[대칭키와-공개키-암호#공개키-암호|공개키 쌍]]
- `Address`: 가상 장치의 가상 IP
- `Endpoint`: 바깥 IP 헤더에 들어갈 주소
- `AllowedIPs`: 라우팅 테이블. `10.0.0.0/8`로 바꾸면 분할 터널이 된다

## VPN이 지켜주는 것과 못 지켜주는 것

이미 대부분의 사이트가 [[http와-https|HTTPS]]를 쓰기 때문에, **내용**은 VPN 없이도 암호화되어 있다. VPN이 더해 주는 것은 주로 **어디에 접속하는지**와 **내 IP**를 숨기는 것이다.

| 지켜주는 것 | 못 지켜주는 것 |
| --- | --- |
| 공용 와이파이·통신사가 내가 접속하는 사이트를 보는 것 | VPN 업체가 보는 것 |
| 사이트가 내 실제 IP와 대략적인 위치를 아는 것 | 로그인한 계정, 쿠키, 브라우저 정보(핑거프린팅)로 나를 알아보는 것 |
| HTTP(암호화 안 된) 사이트의 내용이 와이파이에서 보이는 것 | VPN 서버에서 목적지까지 구간의 HTTP 내용 |
| 내부망에 밖에서 안전하게 들어가기 | 피싱 사이트, 악성 코드, 해킹당한 사이트 |

**VPN은 익명화 도구가 아니다.** 구글에 로그인한 채로 VPN을 켜면, 구글은 IP만 바뀐 같은 사람으로 본다.

## 새는 곳 막기

VPN을 켜도 일부 통신이 터널 밖으로 새면 숨긴 정보가 드러난다.

| 누출 | 원인 | 막는 방법 |
| --- | --- | --- |
| **[[dns]] 누출** | 사이트 주소를 묻는 DNS 질문만 터널 밖의 통신사 DNS로 나간다. 통신사가 내가 가는 도메인을 다 본다 | VPN 설정에서 터널 안의 DNS 서버를 쓰게 한다 |
| **IPv6 누출** | VPN이 IPv4만 터널로 보내고, IPv6 통신은 그대로 나간다 | IPv6도 터널로 보내거나 막는다 |
| **WebRTC 누출** | 브라우저의 화상 통화 기능이 내 실제 IP를 알아내 상대에게 알려줄 수 있다 | 브라우저 설정이나 확장 프로그램으로 막는다 |
| **연결 끊김** | VPN이 잠깐 끊긴 사이 통신이 그대로 나간다 | **킬 스위치**: VPN이 끊기면 모든 통신을 막는다 |

## VPN, 프록시, Tor 비교

| | 프록시 | VPN | Tor |
| --- | --- | --- | --- |
| 동작 위치 | 특정 프로그램(브라우저 등) | 운영체제 전체 | Tor 브라우저 |
| 암호화 | 보통 없다 (HTTPS 프록시는 예외) | 있다 | 있다 (여러 겹) |
| 거치는 서버 | 1개 | 1개 | 3개 (각각 앞뒤만 안다) |
| 내 정보를 아는 쪽 | 프록시 운영자 | VPN 업체 | 한 서버가 다 알지 못한다 |
| 속도 | 빠르다 | 약간 느려진다 | 많이 느리다 |

- **프록시**는 대신 요청해 주는 중개 서버다. 암호화 없이 IP만 바꾸는 경우가 많다.
- **Tor**는 서버 세 곳을 거치며 암호를 양파처럼 여러 겹 씌운다. 첫 서버는 나를 알지만 목적지를 모르고, 마지막 서버는 목적지를 알지만 나를 모른다. 신뢰를 한 곳에 몰지 않는 대신 매우 느리다.

## 느려지는 이유

- **돌아가는 길:** VPN 서버를 거쳐야 해서 경로가 길어진다. 먼 나라의 서버일수록 느리다.
- **헤더가 늘어난다:** 겉봉투 헤더가 붙는 만큼 패킷 하나에 실을 수 있는 데이터가 줄어든다. 한 번에 보낼 수 있는 크기(MTU)를 넘으면 패킷이 쪼개져서 더 느려진다. 그래서 VPN은 가상 장치의 MTU를 1,500보다 작게(WireGuard 기본 1,420) 잡는다.
- **암호화 계산:** 요즘 기기에서는 거의 체감되지 않는다.

## 알아둘 점

- 한국에서 VPN을 쓰는 것 자체는 불법이 아니다. 회사와 학교에서도 널리 쓴다.
- 다만 서비스 **약관**에서 VPN을 금지하는 경우가 있다. 예를 들어 지역별 가격이나 콘텐츠를 VPN으로 우회하면 계정이 정지될 수 있다. 게임은 VPN 접속을 부정행위로 보기도 한다.
- VPN은 접속 기록을 숨기는 도구가 아니라 **통신 구간을 보호하는 도구**다. 불법 행위를 VPN이 덮어 주지는 않는다. → [[정보통신망법]]
- 나라에 따라 허가받지 않은 VPN을 막거나 금지한다. 그런 나라에서는 통신 내용을 깊이 들여다보는 장비(DPI)로 VPN 통신의 모양을 알아내서 차단하기도 한다.

## 직접 확인하기

- **IP 확인:** VPN을 켜기 전과 후에 "what is my ip" 같은 사이트에 접속해 보면 나오는 IP와 나라가 바뀐다.
- **DNS 누출 확인:** "dns leak test" 사이트에서 내 DNS 질문이 어느 서버로 가는지 볼 수 있다. 통신사 이름이 나오면 새고 있는 것이다.
- **경로 확인:** `tracert google.com`(윈도우)을 VPN 전후로 비교하면, VPN을 켠 뒤에는 첫 구간이 터널 안의 주소(예: `10.8.0.1`)로 바뀐다.
- **가상 장치 확인:** `ipconfig`(윈도우)나 `ip addr`(리눅스)에 VPN 장치와 가상 IP가 새로 보인다.
