## 레이캐스팅이란

**레이캐스팅(Raycasting)**은 한 점에서 어떤 방향으로 **광선(ray)을 쏘아서, 처음 부딪히는 물체가 무엇이고 얼마나 떨어져 있는지** 알아내는 방법이다.

이 말은 두 가지 뜻으로 쓰인다.

| 뜻 | 하는 일 | 예 |
| --- | --- | --- |
| **넓은 뜻: 광선 판정** | 광선 하나가 무엇에 맞는지 계산 | 총알 판정, 마우스로 클릭한 물체 찾기, 바라보는 블록 찾기 |
| **좁은 뜻: 2.5D 렌더링** | 화면의 세로줄마다 광선을 쏘아 벽을 그림 | 1992년 《Wolfenstein 3D》 같은 초기 1인칭 게임 |

넓은 뜻의 예로, [[mode|Fantasy Economy]] 모드는 플레이어가 양동이를 쓸 때 시선 방향으로 광선을 쏘아(`player.pick`) 어느 블록에 물을 붓는지 찾고, 그 자리가 보호된 땅인지 확인한다.

이 문서는 주로 **2.5D 렌더링으로서의 레이캐스팅**과, 그 핵심인 **DDA 알고리즘**을 정리한다.

### 레이트레이싱·레이마칭과의 차이

| 방법 | 광선 수 | 반사·굴절 | 속도 | 쓰임 |
| --- | --- | --- | --- | --- |
| **레이캐스팅** | 화면 가로 픽셀 수만큼 (예: 640개) | 없음. 처음 맞은 곳에서 멈춘다 | 매우 빠름 | 초기 FPS, 미니맵 시야, 충돌 판정 |
| **레이트레이싱** | 픽셀마다 하나 이상 | 맞은 뒤 다시 튕겨 나간다 | 느림 | 사실적인 조명, 영화 CG |
| **레이마칭** | 픽셀마다 하나 | 구현에 따라 다름 | 중간 | 셰이더로 그리는 구름·연기·수식 도형 |

레이캐스팅은 "보이는 첫 벽까지만" 계산하기 때문에, 1990년대 PC로도 실시간으로 3D처럼 보이는 화면을 그릴 수 있었다.

## 2.5D 렌더링의 원리

### 세계는 2D 격자

맵은 칸으로 나뉜 2D 격자이고, 각 칸은 **벽(1)** 아니면 **빈 칸(0)** 이다.

```text
1111111111
1000000001
1001100001
1000000001
1111111111
```

플레이어는 이 평면 위의 한 점에 서 있다. 높이 개념이 없기 때문에 **모든 벽은 높이가 같고, 위아래를 올려다볼 수 없다.**
진짜 3D가 아니라 2D 맵을 3D처럼 보이게 그리는 것이라 **2.5D**라고 부른다.

### 플레이어와 카메라 평면

플레이어 상태는 벡터 세 개로 나타낸다.

| 벡터 | 뜻 | 예 |
| --- | --- | --- |
| `pos` | 플레이어 위치 | `(22.0, 12.0)` |
| `dir` | 바라보는 방향 (길이 1) | `(-1, 0)` |
| `plane` | **카메라 평면**. `dir`에 수직인 벡터 | `(0, 0.66)` |

![[레이캐스팅-카메라-평면.svg]]

카메라 평면은 "화면"이 세계 안에 놓인 위치라고 생각하면 된다. `pos + dir`이 화면 한가운데이고, 왼쪽 끝은 `pos + dir − plane`, 오른쪽 끝은 `pos + dir + plane`이다.

화면의 세로줄 `x`(0부터 `w−1`까지)마다 카메라 평면 위의 점을 하나 고르고, 그 점을 지나는 광선을 쏜다.

```text
cameraX = 2 · x / w − 1          // 왼쪽 끝 −1, 가운데 0, 오른쪽 끝 +1
rayDir  = dir + plane · cameraX
```

### 시야각(FOV)

시야각은 `dir`과 `plane`의 길이 비율로 정해진다.

```text
FOV = 2 · atan(|plane| / |dir|)
```

`|dir| = 1`, `|plane| = 0.66`이면 `2 · atan(0.66) ≈ 66.8°`로, 1인칭 게임에서 흔히 쓰는 시야각이 된다.
`plane`을 길게 하면 시야가 넓어지고(광각), 짧게 하면 좁아진다(망원).

### 광선을 쏘고 벽까지의 거리 구하기

각 광선은 격자를 따라가다가 **처음 만나는 벽 칸**에서 멈춘다. 이 과정을 빠르고 정확하게 하는 방법이 아래의 [DDA 알고리즘](#dda-알고리즘)이다.

![[레이캐스팅-광선.svg]]

위 그림은 빨간 점(플레이어)에서 왼쪽 위를 바라보며 광선 41개를 쏜 모습이다.
파란 점은 **세로 벽면**(x 방향 경계)에, 초록 점은 **가로 벽면**(y 방향 경계)에 맞은 곳이다.
실제로는 화면 가로 픽셀 수만큼, 보통 수백 개를 쏜다.

### 벽 높이 정하기

멀리 있는 물체는 작게 보인다. 그래서 벽까지의 거리에 **반비례**하게 세로줄 높이를 정한다.

```text
lineHeight = h / perpWallDist        // h: 화면 높이
drawStart  = h / 2 − lineHeight / 2
drawEnd    = h / 2 + lineHeight / 2
```

세로줄 `x`의 `drawStart`부터 `drawEnd`까지를 벽 색으로 칠하고, 위는 천장, 아래는 바닥 색으로 칠한다.
이것을 모든 `x`에 대해 반복하면 한 프레임이 완성된다.

### 어안 효과와 수직 거리

여기서 거리로 **실제 직선 거리(유클리드 거리)**를 쓰면 화면 가장자리의 벽이 둥글게 휘어 보인다. 이것을 **어안(fisheye) 효과**라고 한다.

이유는 이렇다. 정면의 평평한 벽을 볼 때, 가장자리로 갈수록 광선이 비스듬히 가서 실제 거리가 길어진다.

```text
유클리드 거리 = 수직 거리 / cos(θ)      // θ: 광선과 dir 사이 각도
```

그래서 평평한 벽인데도 가장자리가 낮게 그려져 둥글어진다.
사람 눈이나 카메라에서 평평한 벽은 평평하게 보여야 하므로, **카메라 평면까지의 수직 거리**(`perpWallDist`)를 써야 한다.

DDA를 쓰면 이 수직 거리가 **추가 계산 없이 바로 나온다.** 이유는 [수직 거리가 바로 나오는 이유](#수직-거리가-바로-나오는-이유)에 정리했다.

### 회전

방향을 바꿀 때는 `dir`과 `plane`을 **같은 각도로 함께** 회전시킨다. 2D 회전 행렬을 쓴다.

```text
x' = x · cos(a) − y · sin(a)
y' = x · sin(a) + y · cos(a)
```

둘을 같이 돌려야 `plane`이 계속 `dir`에 수직으로 남고, 시야각도 유지된다.

### 면 구분과 텍스처

- **면 구분:** 광선이 세로 벽면(`side = 0`)에 맞았는지 가로 벽면(`side = 1`)에 맞았는지에 따라 한쪽을 조금 어둡게 칠하면, 모서리가 구분되어 입체감이 생긴다.
- **텍스처:** 벽의 어느 지점에 맞았는지(`wallX`, 0~1)를 구해서 텍스처 이미지의 몇 번째 세로줄을 쓸지 정한다.

```text
wallX = (side == 0) ? posY + perpWallDist · rayDirY
                    : posX + perpWallDist · rayDirX
wallX = wallX − floor(wallX)          // 소수 부분만 = 칸 안에서의 위치
texX  = floor(wallX · texWidth)
```

### 한계

- 벽 높이가 모두 같고, 층이나 경사를 표현하기 어렵다.
- 위아래로 고개를 돌릴 수 없다. 화면을 위아래로 밀어서 흉내 내는 정도만 가능하다.
- 벽이 격자에 맞춘 직각이어야 한다. 비스듬한 벽은 다른 방법(예: 《DOOM》의 BSP)이 필요하다.

## DDA 알고리즘

### DDA란

**DDA(Digital Differential Analyzer)**는 원래 **두 점 사이의 직선을 픽셀로 그리는** 알고리즘이다.
두 점의 차이(`Δx`, `Δy`)를 일정한 걸음으로 나누어 조금씩 나아가며 점을 찍는다.

```text
steps = max(|Δx|, |Δy|)
xInc  = Δx / steps
yInc  = Δy / steps

x = x0, y = y0
steps번 반복:
    점 찍기 (round(x), round(y))
    x += xInc
    y += yInc
```

이 방식은 **한 걸음마다 픽셀 하나**를 찍기 때문에 선이 끊기지 않는다. 다만 선이 모서리를 살짝 스치는 칸은 건너뛸 수 있다.
정수만 써서 같은 일을 더 빠르게 하는 방법이 **브레젠험(Bresenham) 알고리즘**이다.

### 레이캐스팅에서의 DDA

레이캐스팅에서는 "점을 찍는 것"이 아니라 **광선이 지나가는 칸을 하나도 빠짐없이 차례로 검사하는 것**이 목적이다.
그래서 같은 이름으로 부르지만 조금 다른 방식을 쓴다. 1987년 Amanatides와 Woo가 정리한 **격자 순회(grid traversal)** 알고리즘이 이것이다.

### 고정 간격으로 걸으면 안 되는 이유

가장 단순한 방법은 광선을 따라 0.01씩 조금씩 걸으면서 매번 그 칸이 벽인지 확인하는 것이다.

| 문제 | 설명 |
| --- | --- |
| **벽을 뚫는다** | 걸음 사이에 벽 모서리를 스치면 그 칸을 건너뛴다 |
| **느리다** | 걸음을 작게 할수록 확인 횟수가 늘어난다 |
| **거리가 부정확하다** | 걸음 크기만큼 오차가 생긴다 |

DDA는 **다음 칸 경계까지 한 번에 건너뛴다.** 칸마다 정확히 한 번만 확인하고, 경계와 만나는 정확한 거리를 얻는다.

### 핵심 아이디어

광선은 격자를 지나면서 **세로선(x = 정수)** 이나 **가로선(y = 정수)** 을 하나씩 넘는다. 선을 넘을 때마다 다음 칸으로 들어간다.

그러므로 매 단계마다 이렇게 하면 된다.

1. 다음 세로선까지의 거리와 다음 가로선까지의 거리를 비교한다.
2. **더 가까운 쪽**의 선을 넘는다. 즉 x나 y 중 하나로 한 칸 이동한다.
3. 들어간 칸이 벽이면 멈춘다.

![[dda-거리.svg]]

| 변수 | 뜻 |
| --- | --- |
| `sideDistX` | 시작점에서 **처음 만나는 세로선**까지 광선 위의 거리 |
| `sideDistY` | 시작점에서 **처음 만나는 가로선**까지 광선 위의 거리 |
| `deltaDistX` | 세로선 하나에서 **다음 세로선**까지 광선 위의 거리 (항상 같음) |
| `deltaDistY` | 가로선 하나에서 **다음 가로선**까지 광선 위의 거리 (항상 같음) |
| `stepX`, `stepY` | 광선이 x, y로 가는 방향 (`+1` 또는 `−1`) |
| `mapX`, `mapY` | 지금 있는 칸의 좌표 |

그림에서 노란 칸의 숫자는 광선이 지나간 순서다. 0에서 출발해 파란 점(세로선)을 넘으면 x로, 초록 점(가로선)을 넘으면 y로 한 칸 움직인다.

### deltaDist 구하기

광선 위의 점을 `pos + t · rayDir`라고 하자. `t`는 광선을 따라 간 정도다.

x 좌표가 정확히 1 늘어나려면 `t · |rayDirX| = 1`, 즉 `t`가 `1 / |rayDirX|`만큼 늘어나야 한다.

```text
deltaDistX = |1 / rayDirX|
deltaDistY = |1 / rayDirY|
```

광선이 x축에 거의 평행하면(`rayDirY ≈ 0`) `deltaDistY`가 아주 커진다. 가로선을 거의 넘지 않는다는 뜻이고, 실제 그림과도 맞는다.
`rayDirY = 0`이면 0으로 나누게 되는데, 무한대(`Infinity`)로 두면 "가로선은 절대 넘지 않는다"로 자연스럽게 처리된다.

> `t`는 실제 길이가 아니라 `rayDir` 몇 개만큼 갔는지를 센 값이다. 실제 길이로 바꾸려면 `|rayDir|`를 곱해야 한다.
> 하지만 레이캐스팅에서는 오히려 이 `t`가 더 쓸모 있다. 바로 다음 절의 이유 때문이다.

### 수직 거리가 바로 나오는 이유

`rayDir = dir + plane · cameraX`이고, `|dir| = 1`이며 `plane`은 `dir`에 수직이다.
그러면 `rayDir`를 `dir` 방향으로 나눈 성분은 항상 1이다.

```text
rayDir · dir = dir · dir + cameraX · (plane · dir) = 1 + 0 = 1
```

즉 광선 위에서 `t`만큼 가면, **카메라가 바라보는 방향으로는 정확히 `t`만큼** 간 것이다.
따라서 벽에 맞은 지점의 `t`가 곧 카메라 평면까지의 **수직 거리**다. 코사인 보정 없이 어안 효과가 사라진다.

### sideDist 초기값

시작점은 칸 안의 어딘가에 있다. 처음 경계까지는 한 칸 전체가 아니라 **남은 비율만큼만** 가면 된다.

```text
mapX = floor(posX)

rayDirX < 0 이면:  stepX = −1,  sideDistX = (posX − mapX)     · deltaDistX
rayDirX ≥ 0 이면:  stepX = +1,  sideDistX = (mapX + 1 − posX) · deltaDistX
```

y도 같은 방식으로 구한다. 예를 들어 `posX = 3.3`이고 오른쪽으로 간다면, 다음 세로선(x = 4)까지 0.7칸이 남았으므로 `sideDistX = 0.7 · deltaDistX`다.

### 반복

```text
반복:
    if sideDistX < sideDistY:
        sideDistX += deltaDistX
        mapX += stepX
        side = 0                 // 세로 벽면을 넘었다
    else:
        sideDistY += deltaDistY
        mapY += stepY
        side = 1                 // 가로 벽면을 넘었다

    if map[mapY][mapX] 가 벽: 멈춤
```

멈췄을 때 `sideDist`는 이미 한 칸 더 더해진 상태다. 그래서 벽까지의 거리는 한 번 빼서 구한다.

```text
perpWallDist = (side == 0) ? sideDistX − deltaDistX
                           : sideDistY − deltaDistY
```

### 전체 코드 (JavaScript)

```js
function render(ctx, w, h, map, pos, dir, plane) {
  for (let x = 0; x < w; x++) {
    // 1. 이 세로줄의 광선 방향
    const cameraX = (2 * x) / w - 1;
    const rayX = dir.x + plane.x * cameraX;
    const rayY = dir.y + plane.y * cameraX;

    // 2. DDA 준비
    let mapX = Math.floor(pos.x);
    let mapY = Math.floor(pos.y);
    const deltaX = Math.abs(1 / rayX);   // rayX가 0이면 Infinity
    const deltaY = Math.abs(1 / rayY);

    const stepX = rayX < 0 ? -1 : 1;
    const stepY = rayY < 0 ? -1 : 1;
    let sideX = rayX < 0 ? (pos.x - mapX) * deltaX : (mapX + 1 - pos.x) * deltaX;
    let sideY = rayY < 0 ? (pos.y - mapY) * deltaY : (mapY + 1 - pos.y) * deltaY;

    // 3. 벽을 만날 때까지 한 칸씩
    let side = 0;
    while (true) {
      if (sideX < sideY) { sideX += deltaX; mapX += stepX; side = 0; }
      else               { sideY += deltaY; mapY += stepY; side = 1; }
      if (map[mapY][mapX] > 0) break;
    }

    // 4. 수직 거리 → 벽 높이
    const dist = side === 0 ? sideX - deltaX : sideY - deltaY;
    const lineH = Math.floor(h / dist);
    const start = Math.max(0, Math.floor(h / 2 - lineH / 2));
    const end   = Math.min(h - 1, Math.floor(h / 2 + lineH / 2));

    // 5. 그리기 (가로 벽면은 조금 어둡게)
    ctx.fillStyle = side === 0 ? "#c0392b" : "#922b21";
    ctx.fillRect(x, start, 1, end - start + 1);
  }
}
```

이 코드는 맵 가장자리가 모두 벽이라고 가정한다. 가장자리가 열려 있으면 광선이 맵 밖으로 나가므로, `mapX`, `mapY`가 범위를 벗어나는지 확인하거나 최대 거리를 정해 멈춰야 한다.

### 시간 복잡도

- 광선 하나는 **지나가는 칸 수만큼** 반복한다. 맵 크기가 `n × n`이면 최악이라도 약 `2n`번이다.
- 한 프레임은 `화면 너비 × 광선당 칸 수`다. 640px 화면, 20칸 맵이라면 수만 번 정도라서 매우 가볍다.

## 다른 곳에서의 쓰임

### 3D 격자 (복셀)

같은 아이디어를 축 하나 더 늘려 3D 격자에 쓸 수 있다. `sideDistX`, `sideDistY`, `sideDistZ` 중 가장 작은 쪽으로 한 칸씩 간다.
마인크래프트처럼 블록으로 된 세계에서 **바라보는 블록 찾기**, 복셀 렌더링, 시야 판정에 쓰인다.

### 2D 시야와 조명

한 점에서 사방으로 광선을 쏘고, 맞은 지점들을 순서대로 이으면 **그 점에서 보이는 영역(가시 영역)** 이 다각형으로 나온다.
2D 게임의 시야 가리기, 손전등, 그림자 표현에 쓴다.

광선을 많이 쏠수록 실제 모양에 가까워지지만 그만큼 느려진다. 그래서 실제로는 아무 방향으로나 쏘기보다 **벽의 꼭짓점 방향으로만** 쏘아서 적은 광선으로 정확한 다각형을 만드는 경우가 많다.
