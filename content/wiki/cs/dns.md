## DNS란

**DNS(Domain Name System)**는 `google.com` 같은 **도메인 이름**을 `142.250.1.1` 같은 **[[ip-주소와-nat|IP 주소]]**로 바꿔 주는 시스템이다.

컴퓨터는 IP 주소로만 통신한다. 하지만 사람은 숫자를 외우기 어렵다. 그래서 이름을 쓰고, 통신하기 직전에 DNS에 물어서 숫자로 바꾼다.
휴대폰 연락처와 같다. "엄마"를 누르면 휴대폰이 저장된 전화번호로 바꿔서 건다.

DNS가 고장 나면 인터넷 연결이 멀쩡해도 "사이트에 연결할 수 없음"이 뜬다. 주소를 몰라서 찾아가지 못하기 때문이다.

## 도메인의 계층 구조

도메인은 **오른쪽에서 왼쪽으로** 갈수록 범위가 좁아진다.

```text
www.example.co.kr.
                 └ 루트 (보통 생략하는 마지막 점)
               └──── 최상위 도메인(TLD): kr
            └─────── 2단계: co
    └─────────────── example
└─────────────────── 하위 도메인: www
```

| 단계 | 예 | 관리하는 곳 |
| --- | --- | --- |
| **루트** | `.` | 전 세계 루트 서버 13개 이름(A~M). 실제로는 같은 주소를 쓰는 서버 수천 대가 세계 곳곳에 있다 |
| **TLD** (최상위 도메인) | `.com`, `.org`, `.kr`, `.io` | 도메인마다 지정된 기관. `.kr`은 한국인터넷진흥원(KISA) |
| **2단계 이하** | `example.com` | 도메인을 산 사람이나 회사 |

한 서버가 전 세계의 모든 이름을 아는 것이 아니다. 각 단계의 서버가 **바로 아래 단계를 누가 담당하는지만** 안다. 그래서 수억 개의 도메인을 나눠서 관리할 수 있다.

## 조회 과정

![[dns-조회-과정.svg]]

브라우저에 `example.com`을 입력하면 다음 순서로 IP를 찾는다. 그림의 IP 주소는 예시다.

1. **내 컴퓨터의 캐시 확인:** 브라우저와 운영체제가 최근에 찾은 답을 기억하고 있으면 바로 쓴다. `hosts` 파일에 적힌 주소도 이때 쓴다.
2. **리졸버에게 질문(①):** 없으면 **리졸버**에게 묻는다. 리졸버는 대신 답을 찾아 주는 DNS 서버다. 보통 통신사 DNS를 자동으로 쓰고, 구글(`8.8.8.8`)이나 클라우드플레어(`1.1.1.1`)로 바꿀 수도 있다.
3. **리졸버의 캐시 확인:** 리졸버도 최근 답을 기억하고 있으면 바로 돌려준다. 대부분 여기서 끝난다.
4. **루트 서버(②③):** 모르면 루트 서버에 묻는다. 루트 서버는 "`.com`은 저 서버에 물어봐"라고 알려준다.
5. **TLD 서버(④⑤):** `.com` 서버는 "`example.com`은 저 서버가 담당해"라고 알려준다.
6. **권한 있는 서버(⑥⑦):** `example.com`을 실제로 관리하는 서버가 IP 주소를 알려준다.
7. **답(⑧):** 리졸버가 답을 내 컴퓨터에 돌려주고, 자기도 캐시에 저장한다.

리졸버가 루트부터 차례로 물어 가는 것을 **재귀 조회**라고 한다. 내 컴퓨터는 리졸버에게 한 번만 묻고 기다리면 된다.

DNS 질문과 답은 보통 **UDP 53번 포트**로 오간다. 질문 하나, 답 하나로 끝나서 연결을 맺는 TCP보다 빠르기 때문이다.

## 레코드 종류

권한 있는 서버에는 도메인에 대한 정보가 **레코드** 단위로 저장되어 있다.

| 레코드 | 뜻 | 예 |
| --- | --- | --- |
| **A** | 도메인 → IPv4 주소 | `example.com → 93.184.215.14` |
| **AAAA** | 도메인 → IPv6 주소 | `example.com → 2606:2800::1` |
| **CNAME** | 다른 도메인의 별명 | `www.example.com → example.com` |
| **MX** | 이 도메인의 메일을 받을 서버 | `example.com → mail.example.com` |
| **TXT** | 자유로운 글자. 도메인 소유 확인, 스팸 방지 설정 | `"google-site-verification=..."` |
| **NS** | 이 도메인을 담당하는 네임 서버 | `example.com → ns1.example.com` |

GitHub Pages에 직접 산 도메인을 연결할 때도 이 레코드를 쓴다. 도메인 판매 사이트의 DNS 설정에서 A 레코드에 GitHub의 IP를 적거나, CNAME에 `사용자이름.github.io`를 적는다.

## 캐시와 TTL

모든 질문마다 루트 서버부터 묻는다면 너무 느리고, 루트 서버가 감당할 수 없다. 그래서 DNS는 [[캐싱과-캐시|캐시]]를 적극적으로 쓴다.

- 레코드마다 **TTL(Time To Live)**이 붙어 있다. "이 답을 몇 초 동안 기억해도 된다"는 뜻이다. 예: `3600` = 1시간
- 브라우저, 운영체제, 리졸버가 각자 TTL 동안 답을 저장해 두고 재사용한다.

TTL에는 단점도 있다. **서버를 옮겨서 IP를 바꿔도** 이미 캐시된 옛 주소가 TTL 동안 남아 있다. 그래서 "DNS 바꾸고 최대 하루까지 기다리세요"라는 안내가 나온다.
이사가 예정되어 있으면 미리 TTL을 짧게 줄여 두는 것이 요령이다.

캐시를 지우는 명령:

```text
ipconfig /flushdns          (윈도우)
```

## DNS와 개인정보

전통적인 DNS는 **암호화되지 않은 글자**로 오간다. [[http와-https|HTTPS]]로 사이트 내용을 암호화해도, 그 전에 보낸 "`example.com`의 IP가 뭐야?"라는 질문은 중간에서 그대로 보인다.
통신사, 공용 와이파이 관리자는 내가 방문하는 **도메인 목록**을 알 수 있다.

이를 막으려고 DNS를 암호화하는 방법이 나왔다.

| 방식 | 설명 |
| --- | --- |
| **DoH** (DNS over HTTPS) | DNS 질문을 HTTPS 요청에 담아 보낸다. 일반 웹 통신과 구분하기 어렵다. 브라우저 설정의 "보안 DNS"가 이것이다 |
| **DoT** (DNS over TLS) | DNS를 TLS로 암호화해 853번 포트로 보낸다. 안드로이드의 "비공개 DNS"가 이것이다 |

### DNS 누출

[[vpn|VPN]]을 켰는데 DNS 질문만 터널 밖으로 나가 통신사 DNS로 가는 경우가 있다. 이것을 **DNS 누출**이라고 한다. 사이트 내용과 IP는 숨겨도, 어떤 도메인에 가는지는 통신사가 그대로 알게 된다.
좋은 VPN 프로그램은 터널 안의 DNS 서버를 쓰도록 설정을 바꿔서 이를 막는다.

## DNS를 노리는 공격

| 공격 | 내용 | 막는 방법 |
| --- | --- | --- |
| **DNS 스푸핑, 캐시 포이즈닝** | 가짜 답을 끼워 넣어 리졸버가 잘못된 IP를 기억하게 한다. 사용자는 주소창에 진짜 도메인을 쳤는데 가짜 사이트로 간다 | **DNSSEC**: 답에 전자 서명을 붙여 위조를 알아챈다. HTTPS 인증서 확인도 가짜 사이트를 걸러낸다 |
| **hosts 파일 변조** | 악성 코드가 내 컴퓨터의 hosts 파일에 가짜 주소를 적는다 | 백신, hosts 파일 확인 |
| **도메인 탈취** | 도메인 계정을 해킹하거나 만료된 도메인을 남이 사서 레코드를 바꾼다 | 도메인 계정 2단계 인증, 자동 갱신 |
| **DNS 증폭 DDoS** | 작은 질문으로 큰 답을 받는 점을 이용해, 출발지를 피해자 IP로 속여 대량의 답이 피해자에게 쏟아지게 한다 | 아무 질문에나 답하는 공개 리졸버를 운영하지 않는다 |

DNS는 차단에도 쓰인다. 리졸버가 특정 도메인에 대해 진짜 IP 대신 경고 페이지 주소를 돌려주면 그 사이트에 갈 수 없다. 한국의 불법 사이트 차단도 이 방식과, HTTPS 연결 과정에 보이는 도메인 이름(SNI)을 보는 방식을 함께 쓴다.

## 직접 확인하기

```text
nslookup example.com              (윈도우, 맥, 리눅스)
nslookup example.com 1.1.1.1      (특정 리졸버에게 묻기)
dig example.com                   (맥, 리눅스. 더 자세한 정보)
dig example.com MX                (메일 서버 레코드)
```

`ping 8.8.8.8`은 되는데 `ping google.com`이 안 된다면, 인터넷 연결은 정상이고 DNS 문제라는 뜻이다.
