## 머신러닝이란

보통의 프로그램은 사람이 **규칙**을 직접 적는다.

```text
규칙 프로그래밍:  데이터 + 규칙  → 답
머신러닝:        데이터 + 답    → 규칙(모델)
```

**머신러닝**은 반대로, 데이터와 정답을 많이 보여주고 **판단하는 방법을 컴퓨터가 스스로 찾게** 하는 것이다. 이렇게 찾은 판단 방법을 **모델**이라고 한다.

예를 들어 안내문 사진에서 제목 줄을 찾는다고 하자.
- **규칙:** "'안내'라는 글자가 있고 글자가 크면 제목" 같은 조건을 사람이 정한다.
- **머신러닝:** 제목에 표시해 둔 안내문 25장을 보여주면, 모델이 "위쪽에 있을수록, 숫자가 적을수록 제목일 가능성이 높다" 같은 기준과 그 **비중**을 스스로 정한다.

## 규칙과 모델, 무엇을 쓸까

머신러닝이 항상 더 좋은 것은 아니다. **규칙으로 충분하면 규칙이 낫다.** 이해하기 쉽고, 틀렸을 때 고치기 쉽고, 데이터도 필요 없다.

스쿨헬퍼에서 안내문의 종류·제목·날짜를 자동으로 채우려고 할 때 이렇게 정했다.

| 항목 | 규칙으로 해 보니 | 결정 |
| --- | --- | --- |
| 종류 | "수행평가" 단어가 있는지만 봐도 25장 모두 맞음 | **규칙** |
| 제목 | 가장 좋은 규칙이 25장 중 17장(68%)에서 막힘 | **모델** → 20장(80%) |
| 날짜 | 모델을 만들어 봤지만 규칙보다 못함 | **규칙** |

모델은 **규칙이 막히는 곳**에만 쓰고, 모델을 만든 뒤에도 반드시 규칙과 비교한다. 날짜처럼 모델이 규칙을 못 이기면 쓰지 않는다.

## 머신러닝의 종류

| 종류 | 배우는 방법 | 예 |
| --- | --- | --- |
| **지도 학습** | 정답(라벨)이 붙은 데이터로 배운다 | 이 줄이 제목인가? 이 메일이 스팸인가? |
| **비지도 학습** | 정답 없이 데이터의 구조를 찾는다 | 비슷한 손님끼리 묶기 |
| **강화 학습** | 행동해 보고 보상을 받으며 배운다 | 게임하는 AI |

지도 학습은 다시 둘로 나뉜다.
- **분류:** 정해진 종류 중 하나를 고른다. 제목인가 아닌가, 가정통신문인가 수행평가인가.
- **회귀:** 숫자를 예측한다. 내일 기온, 집값.

## 데이터에서 앱까지

```text
1. 데이터 모으기   정답이 붙은 예시를 모은다 (라벨링)
2. 전처리          모델이 읽을 수 있는 표로 바꾼다
3. 특징 만들기     예시마다 판단에 쓸 숫자를 뽑는다
4. 나누기          학습용과 시험용을 나눈다
5. 학습            모델이 학습용 데이터로 기준을 찾는다
6. 평가            시험용 데이터로 얼마나 맞히는지 잰다
7. 적용            앱에 넣고, 실제로 쓰면서 다시 잰다
```

### 1. 데이터와 라벨

**라벨**은 데이터에 붙인 정답이다. 라벨을 붙이는 일을 **라벨링**이라고 하고, 머신러닝에서 가장 시간이 많이 드는 단계다.

- **기준을 먼저 정한다.** 사람마다 정답이 다르면 모델도 헷갈린다. 스쿨헬퍼는 "종류는 내용이 아니라 형식으로 나눈다", "제목은 이 안내문만의 이름이 담긴 줄 하나" 같은 기준표를 먼저 만들었다.
- **쓰면서 모으기:** 스쿨헬퍼는 사용자가 확인 화면에서 고른 값을 그대로 라벨로 저장한다. 앱을 쓰는 것이 곧 데이터를 모으는 일이 된다.

### 2~3. 전처리와 특징

모델은 사진이나 글을 그대로 읽지 못한다. 예시마다 **숫자 몇 개**로 바꿔야 한다. 이 숫자 하나하나를 **특징**(feature)이라고 한다.

| 안내문의 줄 | 특징으로 바꾸면 |
| --- | --- |
| 위치, 크기 | 세로 위치 0.08 (위에서 8%), 글자 높이 비율 1.9 (평균의 1.9배) |
| 글자 내용 | "안내" 포함 1, 숫자 비율 0.05, 글자 수 22 |

- 사진마다 크기가 달라서 좌표를 **0~1 비율**로 바꿨다. 이런 작업을 정규화라고 한다.
- **어떤 특징을 줄지가 모델 성능을 크게 좌우한다.** 스쿨헬퍼의 날짜 모델이 실패한 이유도 "이 날짜가 내 반 날짜인가"를 알려 줄 특징이 없었기 때문이다.

### 4~6. 나누기, 학습, 평가

모델이 **처음 보는 데이터**에서도 잘 맞히는지 재야 한다. 그래서 데이터를 학습용과 시험용으로 나눈다. 데이터가 적을 때는 여러 번 나눠 평균을 내는 **교차검증**을 쓴다. → [[모델-평가]]

### 7. 앱에 넣기

학습은 컴퓨터에서 Python(scikit-learn)으로 하고, 앱에는 **결과만** 넣을 수 있다.

- 로지스틱 회귀 같은 단순한 모델은 결과가 **숫자 몇 개(가중치)**뿐이다. 앱에서는 곱하고 더하기만 하면 된다. 학습 라이브러리를 앱에 넣을 필요가 없다. → [[로지스틱-회귀#앱에-넣기]]
- 앱에서 같은 계산을 다시 짰다면, **같은 데이터로 두 결과가 같은지** 꼭 확인한다. 특징 계산이 조금만 달라도 모델이 엉뚱하게 동작한다.
- 실제로 쓰면서 정확도를 다시 잰다. 스쿨헬퍼는 모델이 고른 답을 따로 저장해서, 사용자가 얼마나 고쳤는지 알 수 있게 했다.

## 기본 용어

| 용어 | 뜻 |
| --- | --- |
| **모델** | 데이터에서 찾은 판단 방법 |
| **학습** (훈련) | 데이터로 모델의 기준(가중치)을 정하는 과정 |
| **특징** (feature) | 판단에 쓰는 입력 숫자 하나 |
| **라벨** | 데이터에 붙인 정답 |
| **가중치** | 특징마다 얼마나 중요하게 볼지 나타내는 숫자. 학습으로 정해진다 |
| **과적합** | 학습 데이터만 외워서, 처음 보는 데이터에서는 못 맞히는 상태 |
| **추론** (예측) | 학습한 모델로 새 데이터의 답을 내는 것 |
