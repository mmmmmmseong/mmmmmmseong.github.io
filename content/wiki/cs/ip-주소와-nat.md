## IP 주소란

**IP 주소**는 인터넷에 연결된 장치마다 붙는 **주소**다. 데이터를 보낼 때 받는 쪽의 IP 주소를 적어야 [[osi-7계층#3계층-네트워크-계층|라우터]]가 길을 찾아 전달할 수 있다.

지금 가장 많이 쓰는 **IPv4** 주소는 32비트 숫자다. 사람이 읽기 쉽게 8비트씩 네 덩어리로 나눠 10진수로 적는다.

```text
192.168.0.10
= 11000000.10101000.00000000.00001010
```

한 덩어리는 0~255이고, 만들 수 있는 주소는 2³² ≈ **약 43억 개**다.

## 네트워크 부분과 호스트 부분

IP 주소는 **어느 네트워크인지**(네트워크 부분)와 **그 안의 어느 장치인지**(호스트 부분)로 나뉜다. 우편 주소의 "○○동"과 "○○번지"와 같다.

어디까지가 네트워크 부분인지는 **서브넷 마스크** 또는 **CIDR 표기**로 나타낸다.

```text
192.168.0.10/24
              └─ 앞 24비트(192.168.0)가 네트워크 부분

서브넷 마스크로 쓰면 255.255.255.0
```

| 표기 | 네트워크 부분 | 이 네트워크 안의 주소 |
| --- | --- | --- |
| `192.168.0.0/24` | 앞 24비트 | `192.168.0.0` ~ `192.168.0.255` (256개) |
| `10.0.0.0/8` | 앞 8비트 | `10.0.0.0` ~ `10.255.255.255` (약 1,677만 개) |
| `203.0.113.7/32` | 32비트 전부 | 그 주소 하나 |

- 같은 네트워크 안의 장치끼리는 [[osi-7계층#2계층-데이터-링크-계층|스위치]]로 바로 통신한다.
- 다른 네트워크로 가는 패킷은 **게이트웨이**(보통 공유기, `192.168.0.1`)로 보낸다. 게이트웨이가 바깥으로 내보낸다.
- 네트워크 주소(`.0`)와 브로드캐스트 주소(`.255`)는 장치에 붙이지 않는다.

## 공인 IP와 사설 IP

43억 개는 많아 보이지만 세계 인구보다 적다. 휴대폰, 컴퓨터, TV, 서버까지 합치면 턱없이 부족하다.
실제로 IPv4 주소를 나눠 주는 최상위 기관(IANA)의 남은 주소는 2011년에 바닥났다.

그래서 주소를 두 종류로 나눠 쓴다.

| | 공인 IP (Public IP) | 사설 IP (Private IP) |
| --- | --- | --- |
| 범위 | 인터넷 전체에서 **하나뿐** | **집·회사 안에서만** 통한다. 다른 집에서 같은 주소를 써도 된다 |
| 받는 곳 | 통신사가 할당 | 공유기가 나눠 줌 (DHCP) |
| 인터넷에서 직접 찾아오기 | 가능 | 불가능 |
| 예 | `203.0.113.7` | `192.168.0.10` |

사설 IP로 쓰기로 정해 둔 대역(RFC 1918)은 세 개다.

| 대역 | 주로 쓰는 곳 |
| --- | --- |
| `10.0.0.0/8` | 회사, 큰 네트워크, VPN |
| `172.16.0.0/12` (`172.16` ~ `172.31`) | 회사, 도커 같은 가상 네트워크 |
| `192.168.0.0/16` | 가정용 공유기 |

이 밖에 `127.0.0.1`은 **루프백** 주소로, 항상 "나 자신"을 가리킨다. 개발할 때 쓰는 `localhost`가 이 주소다.

### 내 IP 두 개

- `ipconfig`(윈도우)나 `ip addr`(리눅스)로 보면 `192.168.0.10` 같은 **사설 IP**가 나온다.
- "내 IP 확인" 사이트에 접속하면 `203.0.113.7` 같은 **공인 IP**가 나온다.

둘이 다른 이유가 바로 NAT다.

## NAT

**NAT(Network Address Translation, 네트워크 주소 변환)**는 공유기가 **사설 IP를 공인 IP로 바꿔서** 내보내는 기술이다. 집 안의 여러 장치가 공인 IP 하나를 함께 쓸 수 있다.

![[nat-공유기.svg]]

### 동작 과정

1. 노트북(`192.168.0.11`)이 구글(`142.250.1.1:443`)에 요청을 보낸다. 출발지는 `192.168.0.11:51000`이다.
2. 공유기가 출발지를 **자기 공인 IP와 새 포트**(`203.0.113.7:40002`)로 바꿔서 내보낸다. 그리고 이 짝을 **NAT 테이블**에 적어 둔다.
3. 구글은 `203.0.113.7:40002`가 보낸 요청으로 알고 그 주소로 응답한다.
4. 응답이 오면 공유기는 NAT 테이블에서 `40002`를 찾아 `192.168.0.11:51000`으로 되돌려 보낸다.

휴대폰과 노트북이 같은 사이트에 같은 포트로 접속해도, 공유기가 **바깥 포트 번호를 다르게** 붙여서 구분한다. 그래서 정확히는 NAPT(포트까지 바꾸는 NAT)라고 부르지만, 보통 그냥 NAT라고 한다.

### 바깥에서는 들어올 수 없다

NAT 테이블에는 **안에서 먼저 나간 통신**만 적힌다. 바깥에서 먼저 `203.0.113.7`로 연결을 시도하면, 공유기는 안의 어느 장치로 보내야 할지 몰라서 버린다.

- 그래서 집 컴퓨터에 서버를 열어도 밖에서는 접속이 안 된다.
- 덕분에 외부의 무작위 공격이 집 안 장치에 직접 닿지 않는 효과도 있다. 하지만 이것은 부수 효과일 뿐이고, NAT는 방화벽을 대신하지 못한다.

### 포트 포워딩

바깥에서 들어오게 하려면 공유기에 규칙을 직접 적는다. 이것을 **포트 포워딩**이라고 한다.

```text
바깥 203.0.113.7:25565 로 오는 연결 → 안쪽 192.168.0.11:25565 로 보내라
```

예를 들어 집 컴퓨터에 마인크래프트 서버를 열 때 이렇게 설정한다. 대신 그 포트는 인터넷 전체에 열리므로, 서버 프로그램의 보안 업데이트와 비밀번호 관리에 신경 써야 한다.

### 통신사도 NAT를 한다

휴대폰 데이터(LTE, 5G)에서는 통신사가 한 번 더 NAT를 한다(CGNAT). 수많은 휴대폰이 공인 IP 몇 개를 나눠 쓴다.
그래서 휴대폰에서 확인한 공인 IP는 나만의 주소가 아니고, 포트 포워딩도 할 수 없다.

## NAT를 넘어 연결하기

NAT 뒤에 있는 두 장치(예: 친구 집 컴퓨터와 내 컴퓨터)는 서로 직접 연결하기 어렵다. 둘 다 "바깥에서 먼저 들어올 수 없는" 상태이기 때문이다.

| 방법 | 원리 |
| --- | --- |
| **중계 서버** | 둘 다 바깥의 서버에 먼저 접속하고, 서버가 데이터를 넘겨준다. 확실하지만 서버 비용이 든다 |
| **홀 펀칭** | 두 장치가 동시에 서로에게 패킷을 보내서 양쪽 공유기의 NAT 테이블에 기록을 만든다. 화상 통화(WebRTC)와 게임이 쓴다 |
| **[[vpn|VPN]]** | 둘 다 같은 VPN에 접속하면 같은 사설망 안에 있는 것처럼 통신한다 |

## IPv6

IPv4 주소 부족을 근본적으로 해결하려고 만든 것이 **IPv6**다.

| | IPv4 | IPv6 |
| --- | --- | --- |
| 길이 | 32비트 | 128비트 |
| 주소 개수 | 약 43억 | 약 3.4 × 10³⁸ |
| 표기 | `192.168.0.10` | `2001:db8::1` (16진수, `:`로 구분) |
| NAT | 거의 필수 | 필요 없다. 장치마다 공인 주소를 줄 수 있다 |

- IPv6에서는 연속된 0을 `::`로 줄여 쓴다. `2001:0db8:0000:0000:0000:0000:0000:0001` = `2001:db8::1`
- 두 방식은 서로 호환되지 않아서, 지금은 IPv4와 IPv6를 **함께** 쓰는 과도기다. 휴대폰 통신망은 IPv6를 많이 쓰고, 오래된 서비스는 IPv4만 지원하는 경우가 많다.
- NAT가 없다는 것은 바깥에서 장치에 직접 닿을 수 있다는 뜻이기도 하다. 그래서 IPv6에서는 공유기의 방화벽 설정이 더 중요하다.

## 확인하는 명령어

| 명령 | 보여주는 것 |
| --- | --- |
| `ipconfig` (윈도우), `ip addr` (리눅스) | 내 사설 IP, 서브넷 마스크, 기본 게이트웨이 |
| `ping 192.168.0.1` | 공유기까지 닿는지 |
| `tracert google.com` (윈도우) | 목적지까지 거치는 라우터. 첫 줄이 보통 공유기다 |
| "내 IP 확인" 사이트 | 바깥에서 보이는 공인 IP |
