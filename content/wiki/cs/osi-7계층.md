## OSI 7계층이란

**OSI 7계층(OSI 7 Layer Model)**은 컴퓨터끼리 데이터를 주고받는 과정을 **일곱 단계로 나눠** 설명하는 모델이다.
국제표준화기구(ISO)가 1984년에 발표했다. OSI는 Open Systems Interconnection(개방형 시스템 상호 연결)의 줄임말이다.

1970~80년대에는 회사마다 네트워크 방식이 달라서, 다른 회사 장비끼리는 통신하기 어려웠다. OSI 모델은 "통신에 필요한 일을 이렇게 나누고, 각 단계가 이것만 책임지자"는 **공통 기준**을 만들려는 시도였다.

> 같은 이름이 들어가지만 [[http-통신과-3계층-구조|3계층 구조]](클라이언트·서버·DB)와는 다른 이야기다. 그쪽은 **프로그램을 역할별로 나누는 설계**이고, OSI 7계층은 **네트워크 통신 과정을 나눈 모델**이다.

## 왜 계층으로 나누나

택배를 생각하면 쉽다.

- 보내는 사람은 **물건을 포장하고 주소만 적는다.** 트럭이 어느 고속도로로 가는지는 몰라도 된다.
- 택배 회사는 **주소를 보고 배송 경로를 정한다.** 상자 안에 무엇이 들었는지는 몰라도 된다.
- 트럭 기사는 **정해진 다음 터미널까지 옮긴다.** 최종 주소는 몰라도 된다.

네트워크도 같다. 각 계층은 **바로 아래 계층의 기능을 가져다 쓰고, 바로 위 계층에 기능을 제공한다.** 다른 계층이 어떻게 동작하는지는 신경 쓰지 않는다.

| 장점 | 설명 |
| --- | --- |
| **분업** | 웹 브라우저 개발자는 랜선과 와이파이의 차이를 몰라도 된다 |
| **교체** | 유선을 와이파이로 바꿔도 위쪽 계층(브라우저, HTTP)은 그대로 동작한다 |
| **문제 찾기** | "케이블 문제인가, 주소 문제인가, 프로그램 문제인가"를 계층별로 좁혀 갈 수 있다 |
| **공통 언어** | "L4 장비", "L7 방화벽"처럼 계층 번호만으로 무엇을 다루는지 바로 통한다 |

| 계층 | 이름 | 하는 일 | 데이터 단위 | 주소·식별자 | 예 | 장비 |
| --- | --- | --- | --- | --- | --- | --- |
| 7 | **응용** (Application) | 사용자 프로그램이 쓰는 통신 규칙 | 데이터 | 도메인, URL | HTTP, DNS, SMTP, SSH | |
| 6 | **표현** (Presentation) | 데이터 형식 변환, 인코딩, 압축, 암호화 | 데이터 | | UTF-8, JPEG, TLS(일부) | |
| 5 | **세션** (Session) | 연결의 시작·유지·종료 관리 | 데이터 | | RPC, NetBIOS | |
| 4 | **전송** (Transport) | 프로그램 사이의 전달, 신뢰성 | 세그먼트 | **포트 번호** | TCP, UDP | L4 스위치, 로드 밸런서 |
| 3 | **네트워크** (Network) | 목적지까지 경로 찾기 | 패킷 | **IP 주소** | IP, ICMP | **라우터** |
| 2 | **데이터 링크** (Data Link) | 같은 네트워크 안의 옆 장비로 전달 | 프레임 | **MAC 주소** | 이더넷, 와이파이 | **스위치** |
| 1 | **물리** (Physical) | 0과 1을 전기·빛·전파 신호로 바꿔 보냄 | 비트 | | 랜선, 광케이블 | 허브, 리피터 |

- 아래에서 위로 머리글자만 따서 "**물데네전세표응**"이라고 외운다.
- 영어권에서는 "**P**lease **D**o **N**ot **T**hrow **S**ausage **P**izza **A**way"(Physical → Application)라는 문장을 쓴다.

## 계층별 설명

### 1계층: 물리 계층

**0과 1을 실제 신호로 바꿔 보내는 계층이다.**
의미는 따지지 않는다. 그저 비트를 전기 신호(랜선), 빛(광케이블), 전파(와이파이)로 바꿔 상대에게 보낸다.

- 케이블의 모양, 핀 배치, 전압, 주파수 같은 것을 정한다.
- **허브**와 **리피터**가 이 계층 장비다. 받은 신호를 증폭해서 그대로 내보낼 뿐, 누구에게 보내는지 구분하지 못한다. 허브는 들어온 신호를 연결된 모든 장비에 뿌린다.
- 인터넷이 아예 안 되면 가장 먼저 의심하는 계층이다. "케이블이 빠졌나?", "와이파이 신호가 약한가?"

### 2계층: 데이터 링크 계층

**같은 네트워크(같은 공유기, 같은 스위치) 안에서 바로 옆 장비에게 정확히 전달하는 계층이다.**

- **MAC 주소**로 장비를 구분한다. 네트워크 카드마다 제조 시 붙는 48비트 주소다. 예: `3C:22:FB:A1:5E:07`. 앞 24비트는 제조사 번호다.
- 데이터를 **프레임** 단위로 묶고, 끝에 오류 검사용 값(FCS)을 붙인다. 받은 쪽에서 계산이 맞지 않으면 신호가 깨진 것으로 보고 버린다.
- **스위치**가 이 계층 장비다. 허브와 달리 어느 포트에 어떤 MAC 주소가 연결됐는지 기억해서, **목적지 포트로만** 보낸다.
- 유선 랜(이더넷, IEEE 802.3)과 와이파이(IEEE 802.11)가 이 계층과 물리 계층을 함께 정의한다.

MAC 주소는 "같은 동네 안에서만" 의미가 있다. 다른 네트워크로 넘어갈 때마다 프레임이 새로 만들어지고 MAC 주소도 바뀐다.

### 3계층: 네트워크 계층

**여러 네트워크를 건너 최종 목적지까지 가는 경로를 찾는 계층이다.**

- **IP 주소**로 목적지를 정한다. 예: IPv4 `142.250.196.110`, IPv6 `2404:6800:4004:827::200e`.
- **라우터**가 이 계층 장비다. 패킷의 목적지 IP를 보고 "다음에 어느 라우터로 넘길지" 정한다. 이것을 **라우팅**이라고 한다.
- 패킷에는 **TTL**(Time To Live) 값이 있다. 라우터를 하나 지날 때마다 1씩 줄고, 0이 되면 버린다. 경로가 꼬여 패킷이 영원히 도는 것을 막는다.
- **ICMP**도 이 계층에 있다. `ping`이 쓰는 프로토콜로, "목적지에 닿았는지", "왜 못 갔는지"를 알려준다.

택배로 치면 2계층은 "다음 터미널까지 옮기기", 3계층은 "최종 주소까지의 전체 경로 정하기"다.

IP 주소와 MAC 주소를 이어주는 **ARP**는 2계층과 3계층 사이에 걸쳐 있다. "IP가 192.168.0.1인 장비의 MAC 주소가 뭐지?"라고 네트워크 전체에 물어보는 프로토콜이다.

### 4계층: 전송 계층

**컴퓨터 안의 어느 프로그램에게 줄지 정하고, 필요하면 데이터가 빠짐없이 순서대로 도착하게 보장하는 계층이다.**

IP 주소는 컴퓨터까지만 찾아간다. 그 컴퓨터에서 브라우저, 게임, 메신저가 동시에 통신하고 있다면 어느 프로그램의 데이터인지 구분해야 한다. 이때 쓰는 것이 **포트 번호**다.

| 포트 | 쓰는 곳 |
| --- | --- |
| 22 | SSH |
| 53 | DNS |
| 80 | HTTP |
| 443 | HTTPS |
| 3306 | MySQL |

IP 주소가 아파트 동·호수라면, 포트 번호는 그 집에 사는 사람 이름이다.

전송 계층의 대표 프로토콜은 두 가지다.

| | TCP | UDP |
| --- | --- | --- |
| 연결 | 먼저 연결을 맺는다 (3-way handshake) | 연결 없이 바로 보낸다 |
| 신뢰성 | 잃어버린 데이터는 다시 보내고, 순서를 맞춘다 | 보내고 끝. 빠지거나 순서가 바뀌어도 모른다 |
| 속도 | 상대적으로 느리다 | 빠르다 |
| 쓰는 곳 | 웹(HTTP/1.1, HTTP/2), 이메일, 파일 전송 | 영상 통화, 실시간 게임, DNS 조회 |

- **TCP의 3-way handshake:** 연결 전에 세 번 신호를 주고받는다.

  ```text
  클라이언트 → 서버   SYN       "연결해도 될까?"
  클라이언트 ← 서버   SYN-ACK   "좋아, 너도 준비됐어?"
  클라이언트 → 서버   ACK       "준비됐어"
  ```

- 영상 통화에서 1초 전 화면이 늦게 도착하면 이미 쓸모가 없다. 다시 받기보다 그냥 넘기는 편이 낫다. 그래서 실시간 서비스는 UDP를 쓴다.
- 최신 HTTP/3는 TCP 대신 UDP 위에 **QUIC**이라는 프로토콜을 올려 쓴다. 신뢰성은 QUIC이 직접 챙기고, 연결 맺는 시간을 줄였다.

### 5계층: 세션 계층

**통신하는 두 프로그램 사이의 대화(세션)를 시작하고, 유지하고, 끝내는 계층이다.**

- 대화 중간에 "여기까지 받았다"는 표시(동기화 지점)를 두어, 끊겼을 때 처음부터가 아니라 그 지점부터 다시 할 수 있게 한다.
- 양쪽이 동시에 말할지, 번갈아 말할지 같은 대화 규칙을 정한다.

실제 인터넷에서는 세션 계층만 따로 담당하는 프로토콜이 거의 없다. 이 역할은 대부분 응용 프로그램이나 TCP, TLS가 나눠 맡는다.
웹 로그인의 "[[flask-세션|세션]]"은 이름이 같지만, OSI의 세션 계층이 아니라 응용 계층에서 만든 개념이다.

### 6계층: 표현 계층

**데이터를 양쪽이 이해할 수 있는 형식으로 바꾸는 계층이다.** 번역가 역할이다.

- **인코딩:** 글자를 UTF-8이나 EUC-KR로 바꾸고 되돌린다. 보내는 쪽과 받는 쪽의 인코딩이 다르면 글자가 깨진다. → [[인코딩과-디코딩]]
- **형식:** [[데이터-형식|JSON, XML]], 이미지(JPEG, PNG), 영상 형식
- **압축:** gzip처럼 데이터를 줄여서 보낸다.
- **암호화:** 보내기 전에 암호화하고, 받은 뒤 복호화한다.

세션 계층처럼 실제로는 따로 존재하기보다 응용 프로그램 안에서 처리되는 경우가 많다.
HTTPS의 암호화를 맡는 **TLS**는 어느 계층에 넣을지 의견이 갈린다. 암호화라는 역할은 6계층에 가깝지만, 실제로는 TCP(4계층) 바로 위, HTTP(7계층) 바로 아래에서 동작해서 "4.5계층"이라고 부르기도 한다.

### 7계층: 응용 계층

**사용자가 쓰는 프로그램이 네트워크를 이용할 때 따르는 규칙이다.**
브라우저 자체가 아니라, 브라우저가 서버와 대화할 때 쓰는 **프로토콜**이 7계층이다.

| 프로토콜 | 하는 일 |
| --- | --- |
| **HTTP / HTTPS** | 웹 페이지 요청과 응답 → [[http-통신과-3계층-구조]] |
| **DNS** | 도메인(`google.com`)을 IP 주소로 바꾼다 |
| **SMTP, IMAP** | 메일 보내기, 메일함 읽기 |
| **FTP** | 파일 전송 |
| **SSH** | 다른 컴퓨터에 안전하게 원격 접속 |
| **DHCP** | 공유기에 접속하면 IP 주소를 자동으로 받아온다 |

## 캡슐화

데이터를 보낼 때는 7계층에서 1계층으로 내려가면서 **각 계층이 자기 정보를 담은 헤더를 앞에 붙인다.** 받을 때는 1계층에서 올라가면서 헤더를 하나씩 떼어 읽는다. 앞의 것을 **캡슐화**, 뒤의 것을 **역캡슐화**라고 한다.

![[osi-캡슐화.svg]]

편지를 봉투에 넣고, 그 봉투를 다시 택배 상자에 넣는 것과 같다. 각 계층은 **자기가 붙인 헤더만** 읽고, 안쪽은 열어 보지 않는다.

| 헤더 | 붙이는 계층 | 담는 정보 |
| --- | --- | --- |
| TCP 헤더 | 4 | 보내는 포트, 받는 포트, 순서 번호, 확인 번호 |
| IP 헤더 | 3 | 보내는 IP, 받는 IP, TTL |
| 이더넷 헤더 | 2 | 보내는 MAC, 받는 MAC |
| FCS (트레일러) | 2 | 오류 검사 값. 이것만 뒤에 붙는다 |

이더넷 프레임 하나에 담을 수 있는 크기(MTU)는 보통 1,500바이트다. IP 헤더와 TCP 헤더가 최소 20바이트씩이라서, 실제 데이터는 한 번에 최대 1,460바이트 정도다. 큰 파일은 여러 조각으로 나눠 보내고 받는 쪽에서 다시 합친다.

## 장비는 필요한 계층까지만 열어 본다

![[osi-장비와-계층.svg]]

데이터가 내 컴퓨터에서 서버까지 가는 동안 여러 장비를 거친다. 모든 장비가 7계층까지 다 열어 보지는 않는다.

- **스위치**는 2계층까지 열어 MAC 주소만 보고 넘긴다.
- **라우터**는 3계층까지 열어 IP 주소를 보고 다음 경로를 정한다. 넘길 때 2계층 헤더(MAC 주소)는 다음 구간에 맞게 새로 붙인다.
- **양 끝의 컴퓨터**만 7계층까지 모두 처리한다.

중간 장비가 4계층 이상을 들여다보는 경우도 있다. 포트 번호를 보는 방화벽이나 L4 로드 밸런서, URL과 내용까지 보는 L7 로드 밸런서와 웹 방화벽(WAF)이 그렇다.

## 웹 페이지 하나를 열 때

브라우저 주소창에 `https://example.com`을 입력하면 대략 이런 일이 일어난다.

1. **DNS 조회 (7계층):** `example.com`의 IP 주소를 DNS 서버에 묻는다. 이 질문 자체도 UDP(4) → IP(3) → 와이파이(2·1)를 거쳐 나간다.
2. **TCP 연결 (4계층):** 받은 IP 주소의 443번 포트로 3-way handshake를 한다.
3. **TLS 핸드셰이크 (4.5~6계층):** 서버 인증서를 확인하고, 암호화에 쓸 키를 정한다.
4. **HTTP 요청 (7계층):** `GET /` 요청을 보낸다. 이 요청은 암호화(TLS) → TCP 헤더 → IP 헤더 → 이더넷·와이파이 헤더가 붙은 뒤 신호로 바뀌어 나간다.
5. **경로 (3계층):** 공유기 → 통신사 → 여러 라우터를 거쳐 서버에 도착한다. 각 라우터는 IP 헤더만 보고 넘긴다.
6. **서버 처리:** 서버는 헤더를 거꾸로 벗겨 HTTP 요청을 꺼내고, 응답(HTML)을 같은 과정으로 돌려보낸다.
7. **표시:** 브라우저가 HTML을 받아 화면에 그린다. 이미지, CSS 파일마다 4~6을 반복한다. 이미 받은 파일은 [[캐싱과-캐시|캐시]]에서 꺼내 쓴다.

## TCP/IP 4계층과 비교

실제 인터넷은 OSI 모델이 아니라 **TCP/IP 모델**로 돌아간다. OSI는 1980년대에 표준 프로토콜까지 함께 만들었지만, 이미 널리 퍼진 TCP/IP에 밀려 프로토콜은 거의 쓰이지 않게 됐다.
그래도 OSI 모델은 계층이 더 잘게 나뉘어 있어서 **설명하고 문제를 찾는 기준**으로 지금도 많이 쓰인다.

| OSI 7계층 | TCP/IP 4계층 | 예 |
| --- | --- | --- |
| 7 응용 | **응용 계층** | HTTP, DNS, TLS |
| 6 표현 | ↑ | |
| 5 세션 | ↑ | |
| 4 전송 | **전송 계층** | TCP, UDP |
| 3 네트워크 | **인터넷 계층** | IP, ICMP |
| 2 데이터 링크 | **네트워크 접근 계층** (링크 계층) | 이더넷, 와이파이 |
| 1 물리 | ↑ | |

- TCP/IP는 OSI의 5·6·7계층을 **응용 계층 하나**로 합쳤다. 실제로도 세션 관리, 인코딩, 암호화를 응용 프로그램이 함께 처리하기 때문이다.
- 1·2계층도 하나로 묶었다. 이더넷이나 와이파이 표준이 두 계층을 함께 정의하기 때문이다.
- 책에 따라 1·2계층을 나눠서 **TCP/IP 5계층**으로 설명하기도 한다.

## 계층별 공격과 방어

보안에서도 "몇 계층 공격"이라는 표현을 자주 쓴다.

| 계층 | 공격 예 | 내용 | 막는 방법 |
| --- | --- | --- | --- |
| 1 | 도청, 전파 방해 | 케이블에 장비를 연결하거나 와이파이 신호를 가로챈다 | 물리적 접근 통제, 무선 암호화(WPA3) |
| 2 | ARP 스푸핑 | 가짜 ARP 응답으로 "내가 공유기"라고 속여 통신을 가로챈다 | 스위치 보안 설정, 암호화 통신(HTTPS) |
| 3 | IP 스푸핑 | 보내는 IP 주소를 속인다 | 라우터에서 출처가 맞지 않는 패킷 거르기 |
| 4 | SYN 플러드 | 연결 요청(SYN)만 잔뜩 보내고 응답하지 않아 서버의 연결 자리를 바닥낸다 | SYN 쿠키, 방화벽 |
| 7 | [[sql-인젝션]], XSS | 프로그램의 입력 처리 허점을 노린다 | 입력 검증, 웹 방화벽(WAF) → [[owasp-top-10]] |

- 일반 방화벽은 주로 **3·4계층**(IP 주소, 포트)을 보고 막는다. 443번 포트로 들어오는 SQL 인젝션은 정상 HTTPS 통신처럼 보여서 통과한다. 그래서 **7계층**의 내용을 보는 웹 방화벽이 따로 필요하다.
- DDoS도 계층으로 나눈다. 3·4계층 DDoS는 많은 양의 트래픽으로 회선과 연결을 막고, 7계층 DDoS는 무거운 페이지를 계속 요청해서 서버 프로그램을 지치게 한다.

## 문제를 찾을 때

인터넷이 안 될 때 **아래 계층부터** 하나씩 확인하면 원인을 빨리 좁힐 수 있다.

| 확인할 것 | 계층 | 방법 |
| --- | --- | --- |
| 케이블, 와이파이 연결 | 1·2 | 랜선 불빛, 와이파이 연결 상태 |
| IP 주소를 받았나 | 3 | `ipconfig`(윈도우), `ip addr`(리눅스) |
| 공유기까지 가나 | 3 | `ping 192.168.0.1` (공유기 주소) |
| 외부까지 가나 | 3 | `ping 8.8.8.8` → 되면 인터넷 연결은 정상 |
| 어디서 막히나 | 3 | `tracert google.com`(윈도우), `traceroute`(리눅스) |
| 도메인이 풀리나 | 7 | `nslookup google.com` → IP는 되는데 도메인이 안 되면 DNS 문제 |
| 포트가 열렸나 | 4 | `Test-NetConnection google.com -Port 443`(파워셸) |
| 웹 서버가 응답하나 | 7 | `curl -I https://google.com` |

`ping 8.8.8.8`은 되는데 웹사이트가 안 열린다면 1~3계층은 정상이고, DNS(7계층)나 그 위의 문제라는 뜻이다.
