> 관련 프로젝트: [[schoolhelper|스쿨헬퍼]] — 오류를 삼키는 바람에 시간표가 몇 달 전 것으로 멈춘 줄 몰랐던 사례

## 오류의 세 종류

| 종류 | 언제 알 수 있나 | 예 |
| --- | --- | --- |
| **문법 오류** | 실행하기 전 (편집기가 빨간 줄로 알려줌) | 괄호를 안 닫음, 오타 |
| **실행 중 오류 (예외)** | 실행하다가 | 인터넷이 끊김, 파일이 없음, 0으로 나눔 |
| **논리 오류** | 결과를 보고 나서야 | 평균을 구하는데 개수로 안 나눔 |

문법 오류는 고칠 때까지 실행되지 않아서 오히려 찾기 쉽다. 이 문서는 두 번째인 **예외**를 다룬다.

## 예외란

**예외(Exception)**는 프로그램이 실행되다가 **계속 진행할 수 없는 상황**을 만났다는 신호다.

코드가 아무리 정확해도 바깥 세상은 마음대로 되지 않는다.
- 와이파이가 끊긴다.
- 서버가 403을 돌려준다.
- 사용자가 숫자 칸에 글자를 넣는다.
- 받은 데이터가 예상과 다른 모양이다.

예외가 생겼는데 아무도 처리하지 않으면 **프로그램이 멈춘다.** 앱이라면 갑자기 꺼진다.

## null

예외 중 가장 흔한 원인이 **null**이다. null은 "값이 없음"을 뜻한다. [[데이터베이스-기초#null|DB의 NULL]]과 같은 뜻이다.

```dart
String? name = null;       // ? 가 붙으면 null일 수 있다는 뜻
print(name.length);        // 오류: 없는 값의 길이를 잴 수 없다
print(name?.length);       // null이면 null을 돌려준다 (오류 없음)
print(name ?? '이름 없음'); // null이면 대신 쓸 값
```

- null을 처음 만든 컴퓨터 과학자 토니 호어는 2009년에 이것을 "10억 달러짜리 실수"라고 불렀다. null 때문에 생긴 오류와 피해가 그만큼 많다는 뜻이다.
- 그래서 Dart, Kotlin 같은 최신 언어는 **null이 될 수 있는 변수에 `?`를 붙이게** 해서, 실행하기 전에 편집기가 위험한 곳을 알려준다(null 안전성).

## 예외를 잡는 방법: try-catch

"이 부분은 실패할 수 있다"는 코드를 `try`로 감싸고, 실패했을 때 할 일을 `catch`에 적는다.

```dart
try {
  final response = await http.get(url);     // 실패할 수 있는 일
  showTimetable(response);
} catch (e) {
  showError('시간표를 불러오지 못했습니다');   // 실패했을 때
} finally {
  hideLoading();                            // 성공하든 실패하든 마지막에
}
```

파이썬은 `try`, `except`, `finally`로 쓴다.

```python
try:
    value = int(input('학년: '))
except ValueError:
    print('숫자를 입력하세요')
```

### 예외는 위로 올라간다

함수 안에서 생긴 예외를 그 함수가 잡지 않으면, 그 함수를 **부른 쪽으로** 올라간다. 끝까지 아무도 잡지 않으면 프로그램이 멈춘다.

```text
화면 (버튼 누름)          ← 여기서 잡아서 "다시 시도" 버튼을 보여준다
 └ 시간표 서비스            ← 잡지 않고 위로 넘긴다
    └ 네트워크 요청  💥 예외 발생
```

**처리할 수 있는 곳에서 잡는다.** 네트워크 코드는 실패했다는 것만 알고, 사용자에게 무엇을 보여줄지는 모른다. 그래서 화면 쪽에서 잡는 경우가 많다.

### 직접 던지기

문제를 발견한 코드가 직접 예외를 만들어 던질 수도 있다(`throw`, 파이썬은 `raise`).

```dart
if (apiKey.isEmpty) throw Exception('NEIS 인증키가 설정되지 않았습니다.');
```

## 오류를 삼키면 안 된다

예외를 잡고 나서 **아무 일도 없던 것처럼** 넘어가는 것을 "오류를 삼킨다"고 한다.

```dart
// 나쁜 예: 실패하면 그냥 null을 돌려준다
Future<Timetable?> getTimetable() async {
  try {
    return await fetchFromServer();
  } catch (e) {
    return null;   // 왜 실패했는지 아무도 모른다
  }
}
```

앱은 꺼지지 않으니 얼핏 안전해 보인다. 하지만 이렇게 하면 **"실패"와 "데이터 없음"을 구분할 수 없다.**

### 스쿨헬퍼에서 일어난 일

스쿨헬퍼 첫 버전이 바로 이 구조였다.

1. 2026년 11월 컴시간이 요청을 막아서 모든 요청이 403으로 실패했다.
2. 서비스 코드가 오류를 잡아서 `null`을 돌려줬다.
3. 화면은 `null`을 받자 저장해 둔 캐시를 보여줬다. 그 캐시는 **8월** 시간표였다.
4. 오류 메시지가 하나도 없어서, 시간표가 몇 달째 멈춰 있다는 것을 한참 뒤에야 알았다.

앱이 꺼졌다면 바로 알아챘을 문제를, 오류를 삼키는 바람에 오래 몰랐던 것이다.

### 고친 방법

```dart
try {
  final rows = await fetchFromServer();
  saveCache(rows);
  return rows;
} catch (_) {
  if (cached != null && !refresh) return cached;  // 캐시가 있으면 쓰되,
  rethrow;                                        // 없거나 새로고침이면 오류를 위로 올린다
}
```

- 화면은 올라온 오류를 받아서 **"서버 응답 오류 (403)" 같은 메시지와 다시 시도 버튼**을 보여준다.
- 캐시를 보여줄 때도, 이미 시간표가 화면에 있으면 그대로 두고 **"새로 받지 못했다"는 알림**을 띄운다.
- 서버가 "데이터 없음"이라고 답한 경우(방학 등)는 오류가 아니라 **빈 시간표**로 따로 처리한다. → [[공공-오픈-api#데이터가-없거나-오류일-때]]

## 좋은 예외 처리 습관

| 습관 | 이유 |
| --- | --- |
| **실패와 빈 결과를 구분한다** | "데이터가 없다"와 "가져오지 못했다"는 사용자에게 전혀 다른 정보다 |
| **사용자에게는 알아들을 수 있는 말로** | `SocketException: Failed host lookup` 대신 "인터넷 연결을 확인하세요" |
| **개발자에게는 자세히** | 원래 오류 내용은 로그로 남긴다. 그래야 원인을 찾는다 |
| **다음 행동을 준다** | 오류 메시지만 띄우지 말고 "다시 시도" 버튼을 둔다 |
| **기다리는 시간에 한계를 둔다** | 서버가 응답하지 않으면 영원히 로딩 중이 된다. 스쿨헬퍼는 10초에서 끊는다 |
| **잡을 것만 잡는다** | 모든 예외를 한꺼번에 잡으면 진짜 버그(코드 실수)까지 숨는다 |

## 비동기 코드에서 주의할 점

인터넷 요청처럼 오래 걸리는 일은 **비동기**로 처리한다. 기다리는 동안 앱이 멈추지 않게 하려는 것이다. Dart에서는 `async`와 `await`를 쓴다.

**`await` 뒤에는 세상이 바뀌어 있을 수 있다.** 요청을 보내고 기다리는 2초 사이에 사용자가 그 화면을 닫았을 수 있다.

```dart
await saveNotice(notice);
if (!mounted) return;   // 화면이 이미 닫혔으면 아무것도 하지 않는다
setState(() { saving = false; });
Navigator.pop(context);
```

스쿨헬퍼 첫 버전의 버그 두 개가 이 문제였다.
- 공지를 저장한 뒤, 이미 닫힌 화면을 다시 그리려고 했다(`setState`).
- 공지 수정 버튼이 이미 닫힌 창을 기준으로 다음 화면을 열려고 했다.

또 `await`를 빠뜨리면 그 작업에서 생긴 예외를 `try-catch`로 잡을 수 없다. 작업이 끝나기 전에 `try` 블록을 벗어나 버리기 때문이다.
