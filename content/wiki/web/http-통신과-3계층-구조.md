## 3계층 구조

3계층 구조(3-Tier Architecture)는 소프트웨어 시스템을 역할에 따라 **프레젠테이션, 애플리케이션(비즈니스 로직), 데이터 계층**의 3단계로 분리한 설계 방식이다.

![[http-3계층-구조.png]]

우리가 알아야 할 것은 윗부분의 **클라이언트, 서버, 데이터베이스**뿐이다.

| 구성 | 역할 | 예 |
| --- | --- | --- |
| **클라이언트** | 사용자가 직접 보고 상호작용하는 화면을 담당한다. | 웹 브라우저, 모바일 앱 화면 |
| **서버** | 시스템의 '두뇌' 역할을 하며, 입력된 데이터를 바탕으로 응답을 생성한다. | 웹/애플리케이션 서버 |
| **데이터베이스** | '기억 저장소' 역할을 하며 시스템의 모든 데이터를 저장 및 관리한다. | 데이터베이스 서버 |

## HTTP: 요청과 응답

클라이언트에서 서버로 **요청**을 하면, 서버는 클라이언트가 보낸 요청에 맞는 **응답**을 생성한다.

여기서 클라이언트와 서버 간의 통신 규격이 바로 **HTTP**다.
클라이언트가 요청하고, 서버가 응답하는 단순한 방식으로 동작한다.

```text
클라이언트 ──── 요청 ────▶ 서버 ◀───▶ 데이터베이스
          ◀─── 응답 ─────
```

클라이언트가 요청하는 URL을 **요청 URL**이라고 한다.

## 요청 URL과 쿼리: 도서관에서 책 찾기

도서관에서 책을 찾는 과정을 예로 들어보자.

### 요청 URL: 도서관의 특정 서가 주소

내가 원하는 책이 있는 '도서관의 정확한 위치 정보'다.

> 예: 서울도서관 3층 인문학실 역사 코너

### 쿼리: 사서에게 건네는 구체적인 검색어 메모지

더 정확한 책을 찾기 위해 사용하는 '상세 조건(검색어)'이다.

> 예: 조선시대 역사책, 3권짜리 세트

### 최종 요청 URL 예시

```text
https://seoul-library.com/humanities/history?period=joseon&volumes=3
```

| 부분 | 도서관 비유 |
| --- | --- |
| `seoul-library.com` | 서울도서관 |
| `/humanities/history` | 인문학실 역사 코너 (서가 주소) |
| `?period=joseon&volumes=3` | 검색어 메모지: 조선시대, 3권짜리 |

쿼리는 `?` 뒤에 `이름=값` 형태로 붙고, 조건이 여러 개면 `&`로 이어 붙인다.
