정찰은 공격의 첫 단계입니다. 대부분의 단서는 **사이트가 이미 공개해 둔 곳**에 있습니다.
CTF 프로젝트의 첫 단계도 정찰로 숨겨진 페이지를 찾는 것입니다.

## 살펴볼 곳

### robots.txt
검색엔진에게 "여기는 수집하지 마세요"라고 알려주는 파일입니다.
**접근을 막는 기능이 아니라 부탁일 뿐**이라서, 오히려 숨기고 싶은 경로 목록이 됩니다.

```text
User-agent: *
Disallow: /admin/        ← "여기 뭔가 있어요"라고 알려주는 셈
```

이 사이트의 `robots.txt`에도 `/admin/`이 적혀 있습니다. 하지만 `/admin`은 GitHub 토큰 없이는 아무것도 할 수 없어서 괜찮습니다. **경로를 숨기는 것이 아니라 권한으로 막는 것**이 핵심입니다.

### 그 밖에
- **페이지 소스와 주석:** 개발 중 남긴 주석, 숨겨진 폼 필드
- **JS 파일:** API 주소, 하드코딩된 키
- **개발자 도구의 네트워크 탭:** 화면에 안 보이는 API 요청과 응답
- **남겨진 파일:** `dev_note.txt`, `.git/`, `backup.zip`, `.env` 같은 테스트·백업 파일
- **sitemap.xml:** 사이트의 전체 페이지 목록

## 인코딩은 암호화가 아니다

정찰에서 자주 보는 Base64 문자열은 **누구나 되돌릴 수 있는 인코딩**입니다.

```bash
echo 'aGVsbG8=' | base64 -d   # hello
```

비밀을 Base64로 바꿔 두는 건 감춘 게 아닙니다. CTF에서는 이 점을 단서로 썼고, [[api-역공학|API 역공학]]에서는 컴시간이 요청 값을 Base64로 보낸다는 걸 분석했습니다.

## 내 사이트에서 지킬 것

- 배포 전에 테스트 파일, 백업, `.env`를 지웁니다. `.gitignore`도 확인합니다. ([[env로-api-키-관리]])
- 숨기고 싶은 경로는 `robots.txt`에 적지 말고 **로그인·권한으로 막습니다.**
- 운영 환경에서는 디버그 모드를 끕니다. ([[flask-세션]] 참고)
