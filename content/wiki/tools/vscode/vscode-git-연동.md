VS Code에는 Git 기능이 기본으로 들어 있다. 다만 **Git 프로그램 자체는 따로 설치**해야 한다(Windows는 Git for Windows).
명령어로 하는 방법은 [[git-자주-쓰는-명령어]]에 정리했다.

## 저장소 내려받기 (clone)

명령 팔레트 → `Git: Clone` → 저장소 주소 입력(또는 GitHub 로그인 후 목록에서 선택) → 저장할 폴더 선택.
다 받으면 "열기"를 눌러 바로 연다.

## 소스 제어 화면 (`Ctrl+Shift+G`)

### 바뀐 것 보기
- 바뀐 파일이 목록으로 나온다. `M`은 수정, `U`는 새 파일(추적 안 됨), `D`는 삭제다.
- 파일을 누르면 **바뀌기 전과 후를 나란히** 보여준다.
- 편집기 줄 번호 옆의 색 막대도 변경 표시다. 초록은 추가, 파랑은 수정, 빨간 삼각형은 삭제다.

### 커밋하기
1. 커밋할 파일 옆의 `+`를 눌러 **스테이징**한다(`git add`). 전부 올리려면 "변경 사항" 제목 옆의 `+`.
2. 위쪽 입력칸에 메시지를 쓴다.
3. `Ctrl+Enter` 또는 "커밋" 버튼.

스테이징 없이 커밋을 누르면 "모든 변경 사항을 커밋할까?"라고 묻는다.

### 올리기·받기
- **동기화(↻) 버튼**은 pull과 push를 한 번에 한다. 상태 표시줄의 `↓1 ↑2`는 받을 커밋 1개, 올릴 커밋 2개라는 뜻이다.
- 처음 push할 때 GitHub 로그인 창이 뜬다. 한 번 로그인하면 기억한다.

### 브랜치
상태 표시줄 왼쪽 아래의 **브랜치 이름**을 누르면 브랜치를 바꾸거나 새로 만들 수 있다.

## 충돌 해결

pull이나 merge에서 같은 줄을 양쪽이 고쳤으면 충돌이 난다. 충돌 난 파일을 열면 이렇게 보인다.

```text
<<<<<<< HEAD
내 쪽 내용
=======
들어온 쪽 내용
>>>>>>> origin/main
```

위에 나오는 버튼으로 고른다.

| 버튼 | 결과 |
| --- | --- |
| Accept Current Change | 내 쪽만 남김 |
| Accept Incoming Change | 들어온 쪽만 남김 |
| Accept Both Changes | 둘 다 남김 (위아래로) |
| Compare Changes | 나란히 비교 |

복잡하면 **Resolve in Merge Editor**를 눌러 3단 화면(내 쪽 / 들어온 쪽 / 결과)에서 고친다.
다 고치고 저장한 뒤, 그 파일을 스테이징하고 커밋하면 끝이다.

## 파일 기록 보기

탐색기 아래쪽의 **타임라인**에 지금 연 파일의 커밋 기록이 나온다. 항목을 누르면 그때와 지금을 비교한다.

## 내려받지 않고 저장소 열기

**GitHub Repositories**(Remote Repositories) 확장을 쓰면, clone 없이 GitHub 저장소를 바로 열어 읽고 고칠 수 있다.

- 명령 팔레트 → `Remote Repositories: Open Remote Repository...` → GitHub 저장소 선택
- 남의 코드를 잠깐 살펴보거나, 오타 하나 고칠 때 편하다.
- 터미널, 코드 실행, 디버깅은 안 된다. 제대로 작업하려면 clone한다.

## .gitignore

`.gitignore`에 적힌 파일은 탐색기에서 **흐리게** 보이고 소스 제어 목록에도 안 나온다. `.env`, `.venv`, `__pycache__`가 흐리게 보이면 제대로 설정된 것이다. ([[env로-api-키-관리]])
