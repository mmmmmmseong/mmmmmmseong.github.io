## 개요

시간표, 학급 공지처럼 여러 곳에 흩어져 있는 학교 정보를 **한 앱에 모아 보는** 인천남동고 학생용 Flutter 앱이다.

| 기능 | 내용 |
| --- | --- |
| **주간 시간표** | 내 반의 이번 주·다음 주 시간표. 휴업일과 학사일정도 함께 나오고, 선택과목 이동수업은 학교에서 쓰는 블록명(A~D)으로 표시한다 |
| **학급 공지** | 전체 공지와 내 반 공지만 모아 보여준다. 수행평가·공지·행사 태그와 상단 고정 |
| **임원 공지 작성** | 반 임원은 아이디로 로그인해 자기 반 공지를 쓰고 고친다 |
| **간단한 시작** | 처음 한 번 학년·반만 고르면 다음부터 바로 내 시간표가 뜬다. 받아 둔 시간표는 인터넷이 끊겨도 볼 수 있다 |

- 코드: Dart 약 1,600줄
- 앱 ID `com.schoolhelper.main`, 갤럭시 S22 울트라 실기기로 테스트

처음에는 **컴시간** 데이터를 역공학해서 읽는 시간표 앱이었다. 2026년 11월 컴시간이 자동 수집을 막으면서 **NEIS 공식 API로 전환**했고, 그 과정에서 공지 기능의 보안 문제도 함께 고쳤다. 첫 버전은 [[schoolhelper-legacy|첫 버전: 컴시간 역공학]]에 따로 정리했다.

## 구조

```text
앱 ─┬─ 시간표 ── NEIS 오픈 API (hisTimetable) ── 학교가 원래 입력하는 공식 데이터
    │            + Supabase elective_blocks ──── 선택과목 블록 정의
    ├─ 공지 ──── Supabase notice 테이블 (RLS)
    ├─ 임원 ──── Supabase Auth + executives 테이블
    └─ 캐시 ──── shared_preferences (설정, 시간표, 학급별 공지)
```

```text
앱 시작 ─┬─ 저장된 설정 있음 ─────────────────────────────▶ 시간표
         └─ 없음 ─▶ 학년·반 선택 ─▶ 역할 선택 ─┬─ 학생 ─────▶ 시간표
                                              └─ 임원 ─▶ 로그인 ─▶ 시간표
시간표 ─(메뉴)─▶ 공지 ─(임원)─▶ 작성·수정
       ─(메뉴)─▶ 초기화: 설정 삭제 + 로그아웃 ─▶ 학년·반 선택
```

## 시간표: 컴시간에서 NEIS로

### 무슨 일이 있었나

- **발견:** 시간표가 8월 데이터에서 멈춰 있었다. 새로고침이 계속 실패했는데, 서비스 코드가 오류를 `null`로 삼켜서 오래된 캐시만 보이고 있었다. 직접 요청해 보니 PC와 폰 모두 **403**이었다.
- **원인:** 2026년 11월 컴시간 페이지에 요청 토큰, 응답 AES 암호화, 난독화된 스크립트가 추가됐다.

### 우회하지 않기로 한 이유

컴시간의 새 보호 장치를 풀어서 읽는 오픈소스 라이브러리(pycomcigan, MIT)가 있었다. 그 방식을 옮겨 오는 안을 검토했지만 버렸다.

- **허락이 없다.** 자동 수집을 막으려고 **일부러 넣은 장치를 해제**하는 것이다. 라이브러리의 라이선스와는 별개로 컴시간의 허락이 없다.
- **계속 깨진다.** 컴시간이 바꿀 때마다 다시 대응해야 한다. 실제로 그 라이브러리도 사흘 사이에 대응 버전이 세 번 나왔다.
- **학교에 피해가 갈 수 있다.** 학생 폰마다 우회 요청을 보내면 학교 IP가 차단될 위험이 있다.

첫 버전의 역공학과 다른 점도 정리했다. 그때는 보호 장치가 없었고, 공개된 응답을 **브라우저와 같은 방식으로** 받았을 뿐이라 우회가 아니었다. 바뀐 것은 데이터 구조가 아니라 **입구**였다. ([[api-역공학]], [[정보통신망법]])

### NEIS 오픈 API

**NEIS**는 학교가 출결과 수업 기록 때문에 원래 시간표를 입력하는 교육부 시스템이다. 그 데이터를 공식 API로 공개한다.

- 학급 하나의 **이번 주 월요일 ~ 다음 주 금요일**을 한 번에 받아서 날짜로 두 주를 나눈다. 주를 바꿀 때 다시 요청하지 않는다.
- 주말에는 다가오는 주를 "이번 주"로 본다.
- 휴업일과 학사일정은 수업 대신 그 이름(예: `재량휴업일`)이 들어온다. 토요일 행(토요휴업일)은 버린다.
- 교시 수가 날마다 달라서(2·6·7교시) 그날 가장 큰 교시까지 채운다.
- 결과 코드를 구분한다. "데이터 없음"은 빈 시간표, 그 밖의 코드는 오류 메시지와 다시 시도 버튼으로 보여준다.
- 인증키는 코드에 넣지 않고 빌드할 때 주입한다(`--dart-define-from-file`). → [[env로-api-키-관리]]

대신 잃은 것도 있다. NEIS에는 **교사 이름과 분반 표시가 없고**, 과목명이 약칭이 아닌 정식 명칭이라 길다(`미적2` → `미적분Ⅰ`).

## 선택과목 블록

이 프로젝트에서 가장 오래 고민한 부분이다.

### 문제

2학년 선택과목 시간에는 학년 전체가 이동반으로 흩어진다. 그런데 NEIS는 **학급 단위** 데이터라 학생 개인이 무엇을 듣는지 모른다. 그대로 보여주면 내 반 시간표에 내가 듣지 않는 과목이 나온다.

### 분석

2학년 모든 반의 같은 시간대를 나란히 비교했다.

- "이동반 번호 → 과목" 배정이 **주 3회 똑같이 반복되는 시간대 묶음이 4개** 있었다.
- 그 시간의 `CLASS_NM`(반 번호)은 실제 반이 아니라 **이동반 번호**(대체로 수업 교실)였다.
- 2-3반 학생 두 명의 실제 시간표 카드와 대조해서, 블록 12칸이 모두 일치하는 것을 확인했다.
- 학교에서 쓰는 블록 문자(A~D)는 학생이 아니라 **시간대**에 붙는 이름이었다. 이것은 데이터에서 알 수 없어서 직접 맞췄다.

### 결정

- 블록 교시에는 과목명 대신 **블록명(A~D)만** 표시한다. 학생은 자기가 A블록에 무엇을 듣는지 알고 있기 때문이다. 처음에는 학생이 블록마다 과목을 고르는 설정 화면을 생각했지만, 이 결정으로 필요 없어졌다.
- 블록 정의는 각 폰이 매주 자동으로 찾지 않고 **Supabase 테이블**(`elective_blocks`)에 둔다.
  - 휴업일이 낀 주는 반복 패턴이 깨져서 자동 탐지가 안 된다.
  - 블록 문자를 모든 학생이 똑같이 봐야 하고, 틀리면 앱을 다시 배포하지 않고 테이블만 고치면 된다.
- 요일·교시만으로 판정하지 않고 **과목까지 일치할 때만** 블록명으로 바꾼다. 휴업일이나 시간표 교체로 그 칸 과목이 바뀌었을 때 잘못 덮지 않기 위해서다.

```text
elective_blocks
  ay, sem    학년도·학기 (NEIS 행과 같을 때만 적용)
  grade      학년
  name       블록명 (A~D)
  slots      [[요일, 교시], ...]
  sections   {"이동반 번호": "NEIS 과목명"}
```

3학년은 반마다 시간표가 따로 짜여 있어 반복되는 배정이 없었다. 그래서 아직 블록이 없다.

## 보안: 공지와 임원 인증

### 발견한 문제

- 공지 테이블의 **RLS(행 단위 보안)가 꺼져 있었고**, 익명 사용자에게 쓰기·삭제·전체 삭제(TRUNCATE) 권한이 열려 있었다. 앱 안에 들어 있는 공개 키만 있으면 **누구나 모든 공지를 지울 수 있었다.**
- 역할 선택 화면에서 누구나 "임원"을 고를 수 있었다.

### 고친 방법

| 항목 | 방법 |
| --- | --- |
| **임원 인증** | Supabase Auth 로그인. 비밀번호를 직접 저장·검증하지 않으려고 직접 만든 "임원 코드" 방식 대신 골랐다 |
| **임원 명단** | 별도 `executives` 테이블. Auth 계정이 있어도 여기 없으면 권한이 없다. 회원가입 화면은 만들지 않고 계정은 SQL로 관리한다 |
| **아이디 로그인** | Auth는 이메일이 필요해서, 앱이 아이디를 내부용 이메일 형식으로 바꿔 보낸다. 사용자는 아이디만 입력한다 |
| **쓰기 권한 (RLS)** | 읽기는 누구나, 쓰기·수정·삭제는 **자기 학급 임원만**. 익명의 쓰기 권한은 회수했다 |
| **학년·반** | 임원의 학년·반은 선택 화면 값이 아니라 `executives`에 등록된 값을 쓴다 |

### DB 제약을 넣은 계기

데이터를 보다가 버그 두 개를 찾았다.

- 앱이 `tag: null`을 직접 보내서 기본값 `공지`가 적용되지 않았다. → 태그는 NOT NULL에 허용값 검사, 앱은 태그가 없으면 키 자체를 빼고 보낸다.
- 학년만 있고 반이 없는 공지는 어떤 필터에도 걸리지 않아 **아무에게도 보이지 않았다.** → 학년과 반은 "둘 다 비었거나 둘 다 값이 있거나"만 허용한다.

작성자(`author_id`)는 기본값이 로그인한 사용자이고 본인 것만 기록할 수 있다. 수정 시각(`updated_at`)은 트리거로 자동 갱신한다.

Supabase 무료 플랜이라 DB 백업과 브랜치가 없다. 그래서 DB 변경은 마이그레이션을 하나씩, 적용 전에 확인하고 진행했다.

## 캐시

캐시는 세 번 바뀌었다. → [[로컬-캐싱]]

| 버전 | 방식 | 문제 |
| --- | --- | --- |
| 1차 (첫 버전) | 한 번 받으면 새로고침 전까지 계속 사용 | 새로고침할 때 캐시를 먼저 지워서, 오프라인이면 시간표가 사라졌다 |
| 2차 | 주별 키 + 12시간 만료 | 지난주 키가 지워지지 않고 계속 쌓였다 |
| **3차 (현재)** | 두 주를 한 번에 받아 키 하나. **"오늘 받았는가"**로 판단 | |

- NEIS 데이터가 하루 단위로 갱신되기 때문에 "받은 날짜가 오늘인지"를 기준으로 삼았다. 앱을 켜 둔 채 날이 바뀌는 경우도 앱으로 돌아올 때 확인한다.
- 네트워크가 실패하면 같은 학급의 지난 캐시를 보여주고, 이미 화면에 시간표가 있으면 그대로 둔 채 알림만 띄운다.
- 주가 바뀐 직후 오프라인이면 지난주 캐시의 "다음 주" 부분을 이번 주로 쓴다.
- 공지 캐시는 학급별로 나눴다. 전에는 키가 하나라서 반을 바꿔도 이전 반 공지가 보였다.

## AI와 협업한 방식

- **직접 한 일:** 문제 발견(시간표가 8월에 멈춤), 우회하지 않는다는 결정, 선택과목 블록 패턴 분석과 학생 시간표 카드 대조, 블록 문자 확인, 기능 범위 결정
- **AI와 함께 한 일:** 선택지 검토(컴시간 우회 vs NEIS, 자동 탐지 vs 테이블, 임원 코드 vs Auth), DB 권한 점검, 마이그레이션과 Dart 코드 작성
- **개발 환경:** Android Studio에서 VS Code로 옮겼다. 실기기 무선 디버깅으로 테스트하고, APK 설치가 1~2분 걸려서 핫 리로드 위주로 작업했다.
- 결정과 이유는 README의 "설계 결정과 고민 기록"에 남겨 두었다.

## 남은 작업

- 여러 반이 모이는 소규모 선택과목은 NEIS에서 반 없이 강의실로만 나와서, 그 과목을 듣는 학생의 시간표는 맞지 않을 수 있다.
- 휴업일이 칸마다 반복 표시된다. 하루 단위로 합쳐 보여주기

- 운영 전: 공개 회원가입 끄기, 테스트 계정 비밀번호 변경
- 기능 아이디어: 현재 교시 강조, 급식, 학사일정, 위젯, 푸시 알림, 다크 모드
