## 개요

시간표, 학급 공지처럼 여러 곳에 흩어져 있는 학교 정보를 **한 앱에 모아 보는** 인천남동고 학생용 [[앱-개발-과정#flutter와-dart|Flutter]] 앱이다. 이 문서는 최신 버전(v5) 기준이다.

| 기능 | 내용 |
| --- | --- |
| **주간 시간표** | 내 반의 이번 주·다음 주 시간표. 오늘 요일과 지금 교시를 강조하고, 과목은 학교에서 쓰는 약칭으로 보여준다. 휴업일은 하루를 한 칸으로 합친다 |
| **다가오는 일정** | 시간표 위 카드에 30일 안의 학사일정과 **내 안내문 날짜**를 날짜 순으로 세 개까지 D-day와 함께 보여준다. 전체 보기로 이번 학기 일정을 월별로 본다 |
| **급식** | 시간표 4교시와 5교시 사이에 요일별 대표 메뉴. 누르면 그날 메뉴·알레르기·열량. 내 알레르기가 든 메뉴에 "주의" |
| **내 선택과목** | 2학년 선택과목 시간(블록)마다 내가 듣는 과목을 골라 두면 시간표에 그 과목이 나온다 |
| **학급 공지** | 전체 공지와 내 반 공지만 모아 보여준다. 수행평가·공지·행사 태그와 상단 고정 |
| **임원 공지 작성** | 반 임원은 아이디로 로그인해 자기 반 공지를 쓰고 고친다 |
| **간단한 시작** | 처음 한 번 학년·반만 고르면 다음부터 바로 내 시간표가 뜬다. 받아 둔 시간표는 인터넷이 끊겨도 볼 수 있다 |
| **내 안내문** (작업 중) | 안내문 사진을 찍으면 글자를 읽고, **직접 학습한 모델이 제목 줄을 골라 두고** 날짜를 미리 채운다. 확인 후 저장하면 다가오는 일정에 함께 나온다 (Android, 개인용) |

## 구조

```text
앱 ─┬─ 시간표 ── NEIS 오픈 API (hisTimetable, SchoolSchedule, mealServiceDietInfo) ── 학교가 원래 입력하는 공식 데이터
    │            + Supabase elective_blocks ──── 선택과목 블록 정의
    ├─ 공지 ──── Supabase notice 테이블 (RLS)
    ├─ 임원 ──── Supabase Auth + executives 테이블
    ├─ 기기 저장 ─ shared_preferences (설정, 시간표·학사일정, 급식, 학급별 공지, 고른 선택과목, 내 알레르기, 안내문 목록)
    └─ 안내문 ── ML Kit 한국어 OCR → 제목 줄 모델(가중치 JSON) + 날짜 규칙 (작업 중)
                 학습: 앱에서 내보낸 JSON → Python 전처리 → scikit-learn → 가중치만 앱에
```

         └─ 없음 ─▶ 학년·반 선택 ─▶ 역할 선택 ─┬─ 학생 ─────▶ 시간표

## 시간표

### 데이터: NEIS 공식 API

시간표는 **[[공공-오픈-api|NEIS 오픈 API]]**에서 받는다. NEIS는 학교가 출결과 수업 기록 때문에 원래 시간표를 입력하는 교육부 시스템이다.

처음([[schoolhelper-v1|v1]])에는 컴시간 데이터를 [[api-역공학|역공학]]해서 읽었다. 2026년 11월 컴시간이 요청 토큰과 응답 암호화로 자동 수집을 막자, **보호 장치를 풀지 않고** 공식 API로 바꿨다. 결정 과정은 [[schoolhelper-v2#우회하지-않기로-한-이유|v2]]에 있다.

- 학급 하나의 **이번 주 월요일 ~ 다음 주 금요일**을 한 번에 받아서 날짜로 두 주를 나눈다. 응답은 [[json|JSON]]이다. 주말에는 다가오는 주를 "이번 주"로 본다.
- 휴업일에는 수업 대신 그 이름(예: `재량휴업일`)이 교시마다 들어온다. 토요일 행은 버리고, 날마다 다른 교시 수에 맞춰 채운다.
- [[공공-오픈-api#데이터가-없거나-오류일-때|결과 코드]]를 구분한다. "데이터 없음"은 빈 시간표, 그 밖은 오류 메시지와 다시 시도 버튼이다.
- 인증키는 코드에 넣지 않고 빌드할 때 주입한다. → [[env로-api-키-관리]]

### 보여주는 방법

- **오늘·지금 교시:** 오늘 요일은 파랑, 지금 교시는 주황으로 강조한다. 쉬는 시간에는 다음 교시를 강조하고, 1분마다 갱신한다. 교시 시각(1교시 08:50, 50분 수업, 점심 12:40~13:40)은 NEIS에 없어서 코드에 상수로 두었다.
- **과목 약칭:** NEIS의 정식 명칭은 칸에 넣기에 길다. 학교에서 쓰는 약칭으로 바꿔 보여준다(`미적분Ⅰ` → `미적2`, `화법과 언어` → `화언`).
- **휴업일 하루 한 칸:** 학사일정이 휴업이고 그날 시간표 행이 모두 휴업 행사명일 때만, 하루를 사선 줄무늬 한 칸으로 합친다. 수업이 하나라도 있으면 시간표대로 보여준다. 휴업이 아닌 날을 휴업으로 잘못 보여주는 쪽이 더 치명적이라 시간표 데이터를 우선했다.
- **NEIS에 없는 것:** 교사 이름과 분반 표시는 없다.

### 다가오는 일정

[[공공-오픈-api#neis에서-쓸-수-있는-다른-데이터|NEIS 학사일정 API]]를 시간표와 함께 받는다.

- 시간표 위 카드에 30일 안의 내 학년 일정과 **내 안내문 날짜**를 세 개까지 `D-4`, `내일`, `오늘`, `진행 중`으로 보여준다. "전체 보기"로 이번 학기 일정을 월별로 본다.
- 하루 한 행씩 오는 데이터를 이어진 날끼리 기간으로 묶는다(2회고사 12.08~11). 주말에만 걸친 행사와 방학 안의 공휴일은 뺀다.
- 라벨은 **휴업**과 **시험** 두 가지만 쓴다. 이름은 받은 그대로 쓴다. 시안에 쓴 "기말고사"가 실제로는 `2회고사`였기 때문이다.

- 안내문 날짜는 종류 태그(가정통신문·수행평가)를 붙여 학교 일정과 구분하고, 누르면 그 안내문이 열린다. **학교 일정과 내 할 일이 한 화면에** 모이는 지점이다.

자세한 내용은 [[schoolhelper-v4#학사일정|v4]]와 [[schoolhelper-v5#다가오는-일정에-안내문-합치기|v5]]에 있다.

### 급식

- 4교시와 5교시 사이 점심 줄에 요일마다 대표 메뉴를 보여준다. 점심시간에는 오늘 칸이 주황색 "지금 점심"이 된다.
- 대표 메뉴는 밥·국·김치·음료를 빼고 **알레르기 번호가 가장 많은 메뉴**를 고른다. 재료가 많은 메뉴가 대개 주 반찬이기 때문이다.
- 내 알레르기(1~19번)를 고르면 그 재료가 든 메뉴에 "주의"가 붙는다. 건강 정보라 이 휴대폰에만 저장한다.

자세한 내용은 [[schoolhelper-v5#급식|v5]]에 있다.

## 선택과목 블록

이 프로젝트에서 가장 오래 고민한 부분이다.

### 문제

2학년 선택과목 시간에는 학년 전체가 이동반으로 흩어진다. 그런데 NEIS는 **학급 단위** 데이터라 학생 개인이 무엇을 듣는지 모른다. 그대로 보여주면 내 반 시간표에 내가 듣지 않는 과목이 나온다.

### 분석

2학년 모든 반의 같은 시간대를 나란히 비교했다.

- "이동반 번호 → 과목" 배정이 **주 3회 똑같이 반복되는 시간대 묶음이 4개** 있었다.
- 그 시간의 `CLASS_NM`(반 번호)은 실제 반이 아니라 **이동반 번호**(대체로 수업 교실)였다.
- 2-3반 학생 두 명의 실제 시간표 카드와 대조해서, 블록 12칸이 모두 일치하는 것을 확인했다.
- 학교에서 쓰는 블록 문자(A~D)는 학생이 아니라 **시간대**에 붙는 이름이었다. 데이터에서 알 수 없어서 직접 맞췄다.

### 블록 정의

블록 정의는 각 폰이 매주 자동으로 찾지 않고 **[[supabase와-baas|Supabase]] 테이블**(`elective_blocks`)에 둔다.
- 휴업일이 낀 주는 반복 패턴이 깨져서 자동 탐지가 안 된다.
- 블록 문자를 모든 학생이 똑같이 봐야 하고, 틀리면 앱을 다시 배포하지 않고 테이블만 고치면 된다.

```text
elective_blocks
  ay, sem    학년도·학기 (NEIS 행과 같을 때만 적용)
  grade      학년
  name       블록명 (A~D)
  slots      [[요일, 교시], ...]
  sections   {"이동반 번호 또는 강의실": "NEIS 과목명"}
```

요일·교시만으로 판정하지 않고 **과목까지 일치할 때만** 블록 교시로 본다. 휴업일이나 시간표 교체로 그 칸 과목이 바뀌었을 때 잘못 덮지 않기 위해서다.

### 내 선택과목

블록 교시에는 블록명(A~D)과 **내가 고른 과목**이 나온다.

- 블록 칸을 누르거나 **내 선택과목** 화면에서 고른다. 선택지는 **학년의 모든 블록 과목**(2학년 13과목)이고, 그 시간에 열리는 과목을 위에 먼저 보여준다.
- **중복 불가:** 한 과목은 한 블록에서만 들으므로, 다른 블록에서 고른 과목은 흐리게 "X 블록에서 고름"으로 나오고 고를 수 없다.
- 고른 **과목명**을 **이 기기에만** 저장한다. 누가 무엇을 듣는지 서버에 남지 않는다.
- 반·교실은 보여주지 않는다. 같은 과목이어도 학생마다 실제 이동반이 달라서 틀린 정보가 될 수 있기 때문이다.
- 안 고른 블록은 점선 칸에 "고르기"로 나오고, 고르지 않아도 블록명은 보인다.

처음([[schoolhelper-v2|v2]])에는 "블록명만 보여주면 학생이 알아서 안다"고 보고 고르는 화면을 만들지 않았다. 써 보니 블록명만으로는 그 시간에 무엇을 듣는지 바로 알 수 없어서 [[schoolhelper-v3#내-선택과목|v3]]에서 결정을 바꿨다.

v3에서는 그 블록 시간에 열리는 과목만 선택지로 보여줬다. 그런데 학교에는 "이 블록은 이 과목" 같은 규칙이 없고, 교육과정의 "택4" 과목 13개가 수강 인원에 따라 시간표에 배정될 뿐이었다. 블록 정의가 실제와 조금만 어긋나도 학생이 자기 과목을 고를 수 없게 되므로, [[schoolhelper-v4#내-선택과목-개편|v4]]에서 13과목 전체에서 고르고 중복만 막도록 바꿨다.

3학년은 반마다 시간표가 따로 짜여 있어 반복되는 배정이 없었다. 그래서 아직 블록이 없고, 메뉴도 숨긴다.

## 디자인 시스템

색·글자·간격·모서리 값을 **[[웹-디자인#디자인-토큰|디자인 토큰]]**으로 정리해 앱 테마로 적용했다. 화면 코드에는 색이나 숫자를 직접 쓰지 않고 토큰 이름만 쓴다.

- **색:** 흰 바탕에 푸른빛 회색, 주 색은 파랑 4단계. 주황은 **지금 교시 칸에만** 써서 눈에 확 띄게 했다. → [[색채-이론#비율이-더-중요하다|강조색은 적게]]
- **글꼴:** IBM Plex Sans KR. 크기는 7단계로만 쓴다. → [[타이포그래피#크기-단계-타입-스케일|크기 단계]]
- **간격:** 4px 단위. 칸과 카드는 그림자 대신 면 색으로 나눈다. → [[웹-여백과-그리드#간격-체계|간격 체계]]
- **상태 배너:** 시간표를 새로 받지 못하면 "M월 D일에 저장한 시간표입니다. [다시 받기]" 배너가 뜬다. 배너는 한 화면에 하나만 띄운다.

자세한 값은 [[schoolhelper-v3#디자인-시스템|v3]]에 정리했다.

## 공지와 임원 인증

| 항목 | 방법 |
| --- | --- |
| **임원 인증** | Supabase Auth 로그인. 비밀번호를 직접 저장·검증하지 않는다 |
| **임원 명단** | 별도 `executives` 테이블. Auth 계정이 있어도 여기 없으면 권한이 없다. 회원가입 화면은 없고 계정은 SQL로 관리한다 |
| **아이디 로그인** | 앱이 아이디를 내부용 이메일 형식으로 바꿔 보낸다. 사용자는 아이디만 입력한다 |
| **쓰기 권한 (RLS)** | 읽기는 누구나, 쓰기·수정·삭제는 **자기 학급 임원만** |
| **데이터 규칙** | 태그 허용값, "학년과 반은 둘 다 비었거나 둘 다 값이 있거나" 같은 DB 제약 |

v1에서는 공지 테이블의 [[rls와-접근-제어|RLS]]가 꺼져 있어서, 앱 안의 [[supabase와-baas#공개-키는-비밀이-아니다|공개 키]]만 있으면 누구나 모든 공지를 지울 수 있었다. 발견한 과정과 고친 방법은 [[schoolhelper-v2#보안-공지와-임원-인증|v2]]에 있다.

## 캐시

| 저장하는 것 | 다시 받는 때 |
| --- | --- |
| 시간표 (학급 정보 + 두 주 분량 + 블록 정의 + 이번 학기 학사일정) | 학년·반 변경, 새로고침, **오늘 받은 것이 아닐 때** |
| 학급별 공지 목록 | 새로고침, 내가 작성·수정·삭제했을 때 |
| 고른 선택과목 (학년도·학기·학년별) | 과목을 고를 때. 초기화해도 남는다 |
| 급식 (이번 주·다음 주 점심) | 오늘 받은 것이 아닐 때. 실패하면 지난 캐시 |
| 내 알레르기 | 고를 때 |
| 내 안내문 목록 + 원본 사진 | 안내문을 저장·수정·삭제할 때 |

- NEIS 데이터가 하루 단위로 갱신되기 때문에 "받은 날짜가 오늘인지"를 기준으로 삼았다. 앱을 켜 둔 채 날이 바뀌어도 앱으로 돌아올 때 확인한다.
- 네트워크가 실패하면 같은 학급의 지난 캐시를 보여주고 상태 배너를 띄운다. 새로고침은 캐시를 먼저 지우지 않는다.
- 캐시 방식은 세 번 바뀌었다. 변천은 [[schoolhelper-v2#캐시-개편|v2]]에, 원리는 [[로컬-캐싱]]에 있다.

## 내 안내문 (작업 중)

학교 안내문을 사진으로 찍으면 **ML Kit 한국어 문자 인식(OCR)**으로 글자를 읽고, 제목과 날짜를 찾아 정리하는 기능이다. 제목은 **직접 모은 데이터로 학습한 모델**이 고른다. Android 전용, 개인용으로 만들고 있다.

![[schoolhelper-ocr.jpg]]

v3 때의 인식 화면이다. 왼쪽은 시험용 이미지, 오른쪽은 실제 가정통신문이다. 파란 상자가 인식한 글자 덩어리(블록)이고, 아래에 블록마다 읽은 글자와 위치, 신뢰도가 나온다.

### 흐름

```text
사진 → OCR(글자 작으면 2배 확대) → 제목 줄 모델이 1등 줄을 제목으로 → 날짜 규칙이 날짜를 채움
     → 사용자가 확인·수정(종류 고르기, 다른 반 날짜 지우기) → 저장 → 다가오는 일정에 표시
                                    └ 고친 값은 다음 학습의 정답 라벨이 된다
```

### 데이터에서 모델까지

1. **라벨 모으기:** 확인 화면에서 사용자가 고른 값을 그대로 정답 라벨로 저장한다. OCR 결과를 줄마다(글자, 좌표, 신뢰도) 함께 남기고, 제목은 고른 줄 번호까지 남긴다. → [[schoolhelper-v4#사용자가-고른-값이-곧-정답-라벨|v4]]
2. **전처리:** 내보낸 JSON을 줄 단위 표로 바꾸고, 좌표를 비율로 맞춘다. 거의 같은 문서는 학습·시험 중 한쪽에만 둔다. → [[schoolhelper-v5#학습-데이터-다듬기|v5]]
3. **모델이 필요한 곳 고르기:** 종류는 "수행평가" 단어 하나로 25장 모두 맞아서 규칙으로 충분했다. 규칙이 68%에서 막힌 **제목**에만 모델을 썼다.
4. **학습과 평가:** 줄 하나를 데이터 하나로 보는 로지스틱 회귀, 특징 8개(위치 4 + 글자 4). 25장뿐이라 5겹 교차검증으로 평가했다.

| 방법 | 제목을 맞힌 문서 (25장 중) |
| --- | --- |
| 가장 좋은 규칙 | 17 (68%) |
| **모델 (위치 + 글자 특징)** | **20 (80%)** |
| 모델 상위 3줄 안에 정답 | 25 (100%) |

5. **앱에 넣기:** 학습 라이브러리 없이 **가중치 숫자만 JSON으로** 넣고, 앱은 곱하고 더하기만 한다. Python과 31장 모두 같은 줄을 고르는 것을 확인했다.

### 날짜는 규칙으로

날짜도 모델을 실험했지만 규칙(F1 0.731)을 넘지 못했다(모델 0.716). 틀린 날짜 대부분이 반별 일정표의 **다른 반 날짜**였는데, 특징에 "내 반" 정보가 없었기 때문이다. 그래서 지금은 규칙으로 날짜를 채우고 사용자가 다른 반 날짜를 지운다. 무엇을 지웠는지도 저장해서, 다음 "내 반" 모델의 학습 라벨로 쓴다. → [[schoolhelper-v5#날짜-모델보다-규칙|v5]]

### OCR 입력 방식

카톡으로 받은 안내문을 해상도별로 비교해 보니, 정확도는 보정 방식보다 **글자 픽셀 크기**에 달려 있었다(줄 높이 15px 미만 68%, 30px 이상 93~94%). 그래서 보정은 넣지 않고, 줄 높이가 25px 미만이면 2배 확대해 다시 인식한다. → [[schoolhelper-v4#ocr-입력-방식-결정-보정-비교-2차|v4]]

## AI와 협업한 방식

- **직접 한 일:** 문제 발견(시간표가 8월에 멈춤), 우회하지 않는다는 결정, 선택과목 블록 패턴 분석과 학생 시간표 카드 대조, 블록 문자 확인, 기능 범위 결정, 디자인 시스템 방향, 안내문 정답 입력과 라벨링 기준, 모델을 쓸 곳과 쓰지 않을 곳 결정
- **AI와 함께 한 일:** 선택지 검토(컴시간 우회 vs NEIS, 자동 탐지 vs 테이블, 임원 코드 vs Auth), DB 권한 점검, 마이그레이션과 Dart 코드 작성, 실기기 화면 확인, OCR 보정 비교 실험과 채점, 전처리·학습·교차검증 코드, Python과 Dart 계산 결과 대조
- **개발 환경:** VS Code와 실기기 [[앱-개발-과정#실제-폰으로-테스트하기|무선 디버깅]]. APK 설치가 1~2분 걸려서 [[앱-개발-과정#핫-리로드|핫 리로드]] 위주로 작업했다.
- 결정과 이유는 README의 "설계 결정과 고민 기록"에 남겨 두었다.

## 남은 작업

- 여러 반이 모이는 소규모 선택과목은 NEIS에서 반 없이 강의실로만 나온다. 2학년 블록 시간의 209호 수업은 블록 정의에 넣어 고를 수 있게 했지만, 블록이 아닌 209호 중국 문화와 3학년 310호 수업은 아직 맞지 않을 수 있다.
- 학기가 바뀌면 블록 정의 추가, 3학년 블록 구조 확인, 다른 학년 과목 약칭
- 운영 전: 공개 회원가입 끄기, 테스트 계정 비밀번호 변경
- 학사일정: 시험 기간의 "진행 중" 표시, 1·2월의 2학기 범위를 실기기에서 아직 확인하지 않았다.
- 내 안내문: 제목 모델이 "…안내드립니다" 본문 줄을 고르는 오답 개선, 날짜 모델에 "내 반·블록" 특징 추가, 종류 규칙 적용, 데이터 더 모으기
- 기능 아이디어: 위젯, 푸시 알림, 다크 모드
