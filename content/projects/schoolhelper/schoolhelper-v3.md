## 내 선택과목

[[schoolhelper-v2|v2]]에서는 블록 교시에 블록명(A~D)만 보여주고, 과목을 고르는 화면은 만들지 않기로 했다. 써 보니 블록명만으로는 **그 시간에 무엇을 듣는지** 알 수 없었다. 그래서 결정을 바꿨다.

- 블록 칸을 누르거나 메뉴의 **내 선택과목** 화면에서 블록마다 듣는 과목을 고른다.
- 고르는 창에는 이동반마다 과목과 교실이 한 줄씩 나오고, 우리 반 시간표에 나오는 과목에는 "우리 반" 표시가 붙는다. "아직 모름"을 고르면 블록명만 보인다.
- 고른 블록 칸은 블록 문자 아래에 과목 약칭이 나온다. 안 고른 블록은 점선 칸에 "고르기"가 나오고, 시간표 위에 안내가 뜬다. 메뉴에는 고른 개수(예: 3/4)가 보인다.

### 과목명이 아니라 이동반 번호를 저장한다

같은 과목이 한 블록에 여러 이동반으로 열리기도 한다(A 블록의 물질과 에너지 1·3반). 과목명으로 저장하면 어느 이동반인지 구분할 수 없어서 **이동반 번호**를 저장한다.
같은 이유로 고르는 창에는 교실을 함께 보여준다. 블록 테이블에 특별실 정보(`rooms`)를 추가했고, 없는 번호는 `학년-번호 교실`로 표시한다.

### 기기에만 저장한다

- 고른 값은 학년도·학기·학년별로 **이 기기에만** 저장한다. 학기가 바뀌면 새로 고른다.
- 서버에 올리지 않으므로 누가 무엇을 듣는지 다른 사람이 알 수 없다. 반 초기화를 해도 지우지 않는다.
- 블록이 없는 학년(1·3학년)은 메뉴 자체를 숨긴다.

## 디자인 시스템

색·글자·간격·모서리 값을 **디자인 토큰**으로 정리해 앱 테마로 적용했다. 화면 코드에는 색이나 크기 숫자를 직접 쓰지 않고 토큰 이름만 쓴다. → [[웹-디자인#디자인-토큰|디자인 토큰]]

| 항목 | 정한 것 |
| --- | --- |
| **색** | 바탕은 흰색, 회색은 푸른빛. 주 색은 파랑 4단계. 주황은 **지금 교시 칸에만**, 빨강은 초기화 글자에만 쓴다 |
| **글꼴** | IBM Plex Sans KR (400~700, SIL OFL) |
| **글자 크기** | 7단계 (28 · 20 · 16 · 15 · 13 · 12 · 11) |
| **간격** | 4px 단위 |
| **모서리** | 6 · 12 · 알약 |
| **구분** | 칸과 카드는 그림자 대신 **면 색**으로 나눈다 |

위키에 정리한 원칙과 연결하면: [[색채-이론#비율이-더-중요하다|강조색은 적게]], [[타이포그래피#크기-단계-타입-스케일|글자 크기 단계]], [[웹-여백과-그리드#간격-체계|4px 간격 체계]], [[웹-여백과-그리드#근접-원칙과-여백|면으로 묶기]], [[오픈소스-라이선스#코드가-아닌-것의-라이선스|글꼴 라이선스(OFL)]]

다크 모드 값은 정해서 보관만 하고, 기능은 아직 없다.

### 화면에 적용한 것

- **시간표:** 칸마다 연한 면, 칸 사이 4px. 오늘은 파랑, 지금 교시는 주황, 고른 블록은 연파랑, 안 고른 블록과 빈 교시는 점선.
- **과목 약칭:** NEIS의 긴 정식 명칭을 학교에서 쓰는 약칭으로 바꿔 보여준다(`미적분Ⅰ` → `미적2`, `화법과 언어` → `화언`). 표에 없는 이름은 받은 그대로 쓴다. 지금은 2학년만 있다.
- **주 선택:** 시간표 위 알약 모양 버튼 두 개(이번 주, 다음 주, 날짜 범위 포함).
- **상태 배너:** 새로 받지 못하면 시간표 위에 "M월 D일에 저장한 시간표입니다. [다시 받기]" 배너가 뜬다. 배너는 한 화면에 하나만, 상태 배너가 블록 고르기 안내보다 먼저다.
- **메뉴:** 머리 부분을 남색으로 반전하고 학년·반과 역할 배지를 보여준다. 역할은 앱바 제목 대신 메뉴에 둔다.

## 내 안내문 (작업 중)

학교에서 받은 안내문을 사진으로 찍으면 글자를 읽어서 정리하는 기능을 시작했다. Android 전용이고 개인용이다.

- 사진을 찍거나 고르면 **ML Kit 한국어 문자 인식(OCR)**으로 줄마다 글자와 위치를 읽는다.
- 릴리스 빌드가 실패해서 고쳤다. 플러그인이 포함하지 않은 다른 언어 모델 클래스를 참조해서, 빌드 최적화 도구(R8)가 오류를 냈다.
- 사진 보정 방식을 비교했다(사진 2장, 정답 대비 문자 오류율).
  - 원본만으로 오류율 **2.6%**. 36줄 중 22줄이 완전히 일치했고, 오류 절반은 줄 앞 `-` 누락이었다.
  - 흑백·대비 조절은 오히려 나빠졌다. 확대·원근 보정은 작은 글씨만 조금 나아졌다.
  - 결론: 단순 보정은 넣지 않는다. 표본이 적어서 카메라 원본 사진으로 다시 비교할 예정이다.
- 앞으로 할 일: 확인 화면(종류·제목·마감일 선택), 안내문 데이터 수집, Colab에서 scikit-learn으로 안내문 종류와 마감일을 추정하는 모델 학습
