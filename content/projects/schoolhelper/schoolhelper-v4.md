**업데이트:** 2026.11.21 ~ 11.22

시간표 위에 **학사일정**을 붙이고, [[schoolhelper-v3|v3]]에서 시작한 **내 안내문**을 실제로 저장하고 모아 볼 수 있게 만든 버전이다. 안내문 기능은 직접 학습한 모델로 종류와 날짜를 추정하는 것이 목표라, 이번 버전은 **학습 데이터를 모으는 단계**까지다.

## 학사일정

- 시간표 위 카드에 **30일 안의 가까운 일정 두 개**를 D-day와 함께 보여준다. 없으면 카드를 숨긴다.
- "전체 보기"를 누르면 이번 학기 일정을 월별로 볼 수 있고, 내 학년만 / 전체 학년을 바꿀 수 있다.
- 데이터는 [[공공-오픈-api#neis에서-쓸-수-있는-다른-데이터|NEIS 학사일정 API]](`SchoolSchedule`)에서 시간표와 함께 받아 같은 캐시에 둔다.

### 받은 데이터를 다듬기

- 학사일정은 **하루에 한 행씩** 온다. 같은 이름·학년·휴업 여부로 이어진 날을 기간 하나로 묶는다(2회고사 12.08~11, 겨울방학 12.31~1.31).
- 주말에만 걸친 행사(토요휴업일)와, 더 긴 휴업 안에 든 행사(겨울방학 중 신정)는 목록에서 뺀다.
- 라벨은 두 가지다. **휴업**(휴업일·공휴일)과 **시험**(이름에 고사·평가·시험이 들어간 것. 학력평가·모의평가 포함).
- 학기 구분 필드가 없어서 월로 정한다(1학기 3~8월, 2학기 9~2월).

### 시안과 실제 데이터 대조

화면 시안을 먼저 만들고, 실제 응답(2026년 8월~2027년 2월, 122건)과 대조했다. 시안에 쓴 "기말고사"는 실제로 `2회고사`, "대학수학능력시험"은 `대수능-휴업일`이었다. 그래서 이름을 바꾸지 않고 **받은 그대로** 쓴다.

## 휴업일 하루 한 칸

예전에는 휴업일에 교시마다 `재량휴업일`이 반복해서 나왔다. 이제 하루를 **한 칸으로 합쳐** 사선 줄무늬 면에 이름을 세로로 쓰고, 아래에 `휴업`을 붙인다.

판정은 **시간표 데이터를 우선**한다.

- 학사일정이 휴업이고, 그날 시간표 행이 **모두** 휴업 행사명일 때만 합친다.
- 수업이 하나라도 있으면 시간표대로 보여준다. 휴업이 아닌 날을 휴업으로 잘못 보여주는 쪽이 훨씬 치명적이기 때문이다.
- 휴업일에도 시간표 API는 전 교시 행을 보내고 과목명 자리에 행사명이 들어온다(개교기념일 ×6). 그래서 "행이 있다"만으로는 수업일인지 알 수 없어 과목명까지 확인한다.
- Flutter의 표에는 칸 합치기 기능이 없어서, 빈 칸 위에 합친 칸을 겹쳐 그렸다.

## 내 안내문

### 확인 화면과 목록

[[schoolhelper-v3|v3]]에서는 사진의 글자를 읽어 보여주기만 했다. 이제 읽은 결과를 확인하고 저장한다.

- **확인 화면:** 종류를 고르고, 사진에서 **제목 줄을 눌러** 고르고, 날짜를 이름과 함께 여러 개 넣고, 메모를 쓴다.
- **날짜를 여러 개 받는 이유:** 수행평가는 반·블록·차시마다 날짜가 달라서 하나로는 부족했다.
- **목록:** 다가오는 날짜 → 날짜 없음 → 지난 것 순서로, D-day와 함께 보여준다.
- **저장:** 목록은 [[로컬-캐싱|기기 저장소]]에 JSON으로, 원본 사진은 앱 문서 폴더에 복사해 둔다. 사진 고르기 도구가 주는 임시 파일은 지워질 수 있기 때문이다.
- 날짜 선택기 같은 기본 화면을 한국어로 바꿨다.

### 사용자가 고른 값이 곧 정답 라벨

이 기능의 최종 목표는 사진만 넣으면 **종류·제목·마감일을 자동으로 추정**하는 것이다. 이를 위해 Colab에서 scikit-learn으로 모델을 직접 학습할 계획이다.

모델을 학습하려면 "정답"이 붙은 데이터가 필요하다. 그래서 확인 화면에서 사용자가 고른 값을 **그대로 학습 라벨로** 쓰도록 설계했다.

- 원본 사진과 함께 OCR 결과를 줄마다 저장한다: 글자, 좌표, 신뢰도, 기울기, 블록 번호, 이미지 크기, 확대 여부
- 제목은 글자뿐 아니라 **사진에서 고른 줄 번호**도 남긴다. 고른 뒤 OCR 오타를 고쳐도 줄 번호는 유지한다. 그래야 "어느 위치의 줄이 제목인가"를 학습할 수 있다.
- 개발용 메뉴로 **여러 장을 한 번에 불러와** 차례로 라벨을 붙이고, 모은 라벨과 OCR 결과를 **JSON 파일 하나로 내보낸다.** 사진은 넣지 않는다.

### 라벨링 기준

사진 26장을 직접 보며 기준표를 정했다. 종류는 **내용이 아니라 형식**으로 나눈다.

| 종류 | 형식 |
| --- | --- |
| **가정통신문** | 학교 공식 양식. "가정통신문" 머리글, 학교 로고와 연락처, 끝에 "학교장 [직인 생략]". 학부모에게 보낸다. 내용이 평가 계획이어도 이 양식이면 가정통신문 |
| **수행평가** | 교과 선생님이 만든 특정 과목 평가 안내. 평가 일시 표, 채점 기준표. 학생에게 보낸다 |

- 처음에는 "활동 공지"까지 세 가지로 나눴지만, 모은 사진에 활동 공지가 거의 없어 뺐다. 종류마다 데이터가 너무 적으면 학습이 안 되기 때문이다.
- 제목은 "이 안내문만의 이름이 담긴 줄 하나"다. 머리글, 학교 표어, 날짜 줄은 제목이 아니다.
- 날짜는 "내가 행동해야 하는 날"만 넣는다. 수행평가라면 내 반·내 블록의 평가일과 제출 마감이다.
- 학생 이름·학번은 가리고, 수집한 사진은 저장소에 올리지 않는다.

### OCR 입력 방식 결정 (보정 비교 2차)

학습 데이터를 모으기 전에 입력 방식부터 정해야 했다. 나중에 바꾸면 처음부터 다시 학습해야 하기 때문이다.

실제로 가장 많이 쓰는 입력인 **카톡으로 받아 저장한 수행평가 안내문 10장**을 해상도별로 30개 만들어, 핵심 정보 74개가 정확히 나오는지 채점했다.

| 입력 | 정확도 |
| --- | --- |
| 고해상도 원본 (3000~4000px) | 93% |
| 1/2 축소 | 93% (처리 시간 절반) |
| 1/4 축소 | 82% |
| 압축본 (1050×1400) | 79% |
| 압축본 2배 확대 | 86% |

- 정확도는 보정 방식보다 **글자의 픽셀 크기**에 달려 있었다. 줄 높이 15px 미만은 68%, 15~20px은 81%, 30px 이상은 93~94%에서 더 오르지 않았다.
- **결정:** 저장된 이미지를 그대로 쓰고, 줄 높이 중앙값이 **25px 미만이면 2배 확대해 다시 인식**한다. 대비·선명화 같은 보정은 넣지 않는다.
- 문서 스캐너는 카톡 저장 이미지에는 쓸 일이 적어 보류했다.
- 남은 오류는 받침·모음 하나 차이(교시→고시, 수행평가→수행평기)라 확대로는 고쳐지지 않는다. 표는 행이 한 줄로 합쳐지고 칸이 `|`로 나뉘어 나온다. 둘 다 다음 단계의 후처리에서 다룬다.
- 실험은 화면을 조작하지 않고, 이미지를 앱 폴더에 넣고 임시 코드로 한꺼번에 인식해 로그로 모았다.
