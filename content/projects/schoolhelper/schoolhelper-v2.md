**업데이트:** 2026.11.20

컴시간이 자동 수집을 막으면서 시간표 소스를 **NEIS 공식 API로 바꾼** 버전이다. 그 과정에서 공지 기능의 보안 구멍도 함께 고쳤다.

## 시간표: 컴시간에서 NEIS로

### 무슨 일이 있었나

- **발견:** 시간표가 8월 데이터에서 멈춰 있었다. 새로고침이 계속 실패했는데, 서비스 코드가 [[예외-처리#오류를-삼키면-안-된다|오류를 null로 삼켜서]] 오래된 캐시만 보이고 있었다. 직접 요청해 보니 PC와 폰 모두 **403**([[http와-https#상태-코드|접근 거부]])이었다.
- **원인:** 2026년 11월 컴시간 페이지에 [[토큰#요청-토큰-csrf-토큰|요청 토큰]], 응답 [[대칭키와-공개키-암호#대칭키-암호|AES 암호화]], [[api-역공학#5-막혔을-때-기술적-보호-조치|난독화]]된 스크립트가 추가됐다.

### 우회하지 않기로 한 이유

컴시간의 새 보호 장치를 풀어서 읽는 오픈소스 라이브러리(pycomcigan, [[오픈소스-라이선스|MIT 라이선스]])가 있었다. 그 방식을 옮겨 오는 안을 검토했지만 버렸다.

- **허락이 없다.** 자동 수집을 막으려고 **일부러 넣은 장치를 해제**하는 것이다. [[오픈소스-라이선스#라이선스가-허락하지-않는-것|라이브러리의 라이선스와는 별개로]] 컴시간의 허락이 없다.
- **계속 깨진다.** 컴시간이 바꿀 때마다 다시 대응해야 한다. 실제로 그 라이브러리도 사흘 사이에 대응 버전이 세 번 나왔다.
- **학교에 피해가 갈 수 있다.** 학생 폰마다 우회 요청을 보내면 [[ip-주소와-nat#공인-ip와-사설-ip|학교 IP]]가 차단될 위험이 있다.

[[schoolhelper-v1|v1]]의 역공학과 다른 점도 정리했다. 그때는 보호 장치가 없었고, 공개된 응답을 **브라우저와 같은 방식으로** 받았을 뿐이라 우회가 아니었다. 바뀐 것은 데이터 구조가 아니라 **입구**였다. ([[api-역공학]], [[정보통신망법]])

### NEIS로 바꾸며 한 일

- 학급 하나의 **이번 주 월요일 ~ 다음 주 금요일**을 한 번에 받는다. **다음 주 시간표 보기**가 생겼다.
- 휴업일·학사일정 행, 토요일 행, 날마다 다른 교시 수를 처리했다.
- [[공공-오픈-api#데이터가-없거나-오류일-때|결과 코드]]를 구분해서 "데이터 없음"은 빈 시간표, 그 밖은 오류 메시지와 다시 시도 버튼으로 보여준다.
- 인증키는 빌드할 때 주입한다(`--dart-define-from-file`). → [[env로-api-키-관리]]
- 응답이 UTF-8 [[json|JSON]]이라 CP949 처리와 그 패키지를 뺐다.

잃은 것도 있다. NEIS에는 **교사 이름과 분반 표시가 없고**, 과목명이 정식 명칭이라 길다(`미적2` → `미적분Ⅰ`). 약칭은 [[schoolhelper-v3|v3]]에서 되살렸다.

## 선택과목 블록: 블록명 표시

2학년 선택과목 시간에는 학년 전체가 이동반으로 흩어지는데, NEIS는 학급 단위라 학생 개인이 무엇을 듣는지 모른다.

- 2학년 모든 반의 같은 시간대를 비교해서, "이동반 번호 → 과목" 배정이 **주 3회 똑같이 반복되는 시간대 묶음 4개**를 찾았다. 그 시간의 `CLASS_NM`은 실제 반이 아니라 이동반 번호였다.
- 2-3반 학생 두 명의 시간표 카드와 대조해 블록 12칸이 모두 일치하는 것을 확인했다. 블록 문자(A~D)는 데이터에 없어서 직접 맞췄다.
- 블록 정의는 [[supabase와-baas|Supabase]] 테이블(`elective_blocks`)에 두었다. 휴업일이 낀 주는 반복이 깨져 자동 탐지가 안 되고, 틀리면 앱 배포 없이 테이블만 고치면 되기 때문이다.
- 이 버전에서는 블록 교시에 **블록명(A~D)만** 표시했다. 학생이 블록마다 과목을 고르는 화면은 만들지 않기로 했는데, [[schoolhelper-v3|v3]]에서 이 결정을 바꿨다.

## 보안: 공지와 임원 인증

### 발견한 문제

- 공지 테이블의 **[[rls와-접근-제어|RLS(행 단위 보안)]]가 꺼져 있었고**, 익명 사용자에게 쓰기·삭제·전체 삭제(TRUNCATE) 권한이 열려 있었다. 앱 안에 들어 있는 [[supabase와-baas#공개-키는-비밀이-아니다|공개 키]]만 있으면 **누구나 모든 공지를 지울 수 있었다.**
- 역할 선택 화면에서 누구나 "임원"을 고를 수 있었다.

### 고친 방법

| 항목 | 방법 |
| --- | --- |
| **임원 인증** | Supabase Auth 로그인. 비밀번호를 직접 저장·검증하지 않으려고 직접 만든 "임원 코드" 방식 대신 골랐다 |
| **임원 명단** | 별도 `executives` 테이블. Auth 계정이 있어도 여기 없으면 권한이 없다. 계정은 SQL로 관리한다 |
| **아이디 로그인** | 앱이 아이디를 내부용 이메일 형식으로 바꿔 보낸다. 사용자는 아이디만 입력한다 |
| **쓰기 권한 (RLS)** | 읽기는 누구나, 쓰기·수정·삭제는 **자기 학급 임원만**. 익명의 쓰기 권한은 회수했다 |

### DB 제약을 넣은 계기

데이터를 보다가 버그 두 개를 찾았다. ([[데이터베이스-기초#제약-조건|제약 조건]]이 무엇인지)

- 앱이 `tag: null`을 직접 보내서 기본값 `공지`가 적용되지 않았다. → 태그는 NOT NULL에 허용값 검사, 앱은 태그가 없으면 키 자체를 빼고 보낸다.
- 학년만 있고 반이 없는 공지는 어떤 필터에도 걸리지 않아 **아무에게도 보이지 않았다.** → 학년과 반은 "둘 다 비었거나 둘 다 값이 있거나"만 허용한다.

작성자(`author_id`)와 수정 시각(`updated_at`, [[데이터베이스-기초#트리거|트리거]]로 자동 갱신) 열도 추가했다. 무료 플랜이라 백업이 없어서 [[데이터베이스-기초#마이그레이션|마이그레이션]]은 하나씩 확인하며 적용했다.

## 캐시 개편

| 버전 | 방식 | 문제 |
| --- | --- | --- |
| 1차 (v1) | 한 번 받으면 새로고침 전까지 계속 사용 | 새로고침할 때 캐시를 먼저 지워서, 오프라인이면 시간표가 사라졌다 |
| 2차 | 주별 키 + 12시간 만료 | 지난주 키가 지워지지 않고 계속 쌓였다 |
| **3차** | 두 주를 한 번에 받아 키 하나. **"오늘 받았는가"**로 판단 | |

- NEIS가 하루 단위로 갱신되기 때문에 날짜를 기준으로 삼았다. 네트워크가 실패하면 같은 학급의 지난 캐시를 보여준다.
- 공지 캐시는 학급별로 나눴다. 전에는 반을 바꿔도 이전 반 공지가 보였다.
