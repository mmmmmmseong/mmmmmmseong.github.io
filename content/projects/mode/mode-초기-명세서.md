개발 전에 작성한 `minecraft_economy_fantasy_rpg_mod_spec_revised.txt`(17장 분량)의 요약이다. 이후 버전은 모두 이 명세서를 기준으로 만들고, 명세에 없던 기능은 따로 표시했다.

## 목표

바닐라 생존 플레이를 그대로 두고, 그 위에 **상업·금융·토지 소유·장비 성장**을 얹는다. 채광·농사·사냥으로 얻은 자원을 팔아 자본을 모으고, 그 자본을 토지와 장비에 투자하는 흐름을 만든다.

## 확정한 기본 방향

| 항목 | 결정 |
| --- | --- |
| 환경 | Minecraft 26.1.2, Fabric Loader, 싱글플레이 우선 (멀티플레이 확장 고려) |
| 경제 모델 | 혼합형: 판매소·주민 거래는 고정 가격, **거래소만 변동 시세** |
| 화폐 | 코인 아이템과 계좌 잔액을 함께 사용 |
| 토지 | 청크 단위로 보호, 증서로 소유권 증명·양도 |
| RPG 성장 | 레벨 대신 **장비·강화·희귀 재료** 중심 |
| NPC | 복잡한 시뮬레이션 없이 정해진 품목과 제한된 재고 |

## 설계 원칙

- **바닐라 우선:** 기존 블록·아이템·주민을 최대한 활용하고 새 아이템은 최소로
- **점진적 확장:** 경제 핵심부터, 금융과 고급 RPG는 나중에
- **명확한 자산 흐름:** 모든 거래에서 아이템·코인·잔액·시장 재고가 함께 맞게 바뀐다
- **서버가 권위:** 화면이나 아이템 설명만으로 잔액·소유권을 정하지 않는다
- **악용 방지:** 복제, 중복 지급, 거래 재실행, 저장 오류로 인한 자산 생성·소멸을 막는다

## MVP 범위

**포함:** 코인과 계좌, 입출금, 고정 가격 판매소, 주민 직업별 거래, 재고 기반 거래소, 거래 기록과 저장, 청크 소유권과 증서, 토지 보호, 바닐라 재료를 쓰는 장비 강화

**뒤로 미룸:** 대출 등 금융 상품, 무역회사 지분, 레벨·스킬 트리, 전용 강화 재료, 대량의 새 무기·방어구

## 정하지 않고 남겨둔 것

가격표, 시세 민감도, 토지 가격, 강화 단계와 비용 같은 **수치는 플레이 테스트로 정하기로** 했다. 먼저 거래와 저장이 정확한지부터 확인하는 것이 원칙이었다.

## 권장 개발 순서

1. 개발 환경 확인 → 2. 코인·계좌·저장 → 3. 판매소·주민 거래 → 4. 거래소 → 5. 거래 기록·오류 복구 → 6. 토지 → 7. 장비 강화 → 8. 금융·고급 콘텐츠

각 단계는 "기능이 돌아간다"가 아니라 **저장 후 유지, 실패 처리, 악용 테스트까지 통과해야 완료**로 본다.
